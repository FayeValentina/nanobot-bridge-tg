# V3-B：消息池统一交给中间模型

2026-10-29，代码已实现，实际发布结果见本文末尾。V3-C 尚未开始。

所有获准的新成员消息先进入同一个中间判断，包括 @、直接回复、昵称和没有称呼的普通消息。
不再由问句正则、昵称子串、关键词匹配、5% 抽样或答后关注名单独立生成主模型回合。
中间模型返回 wake/observe；主模型被唤醒后仍能等待或沉默。普通助手与群友继续共用工具、技能、MCP、记忆和后台能力。

## 接入与持久化

复用一个 Telegram 接收者、SocialStore 和 SocialScheduler。新增协调器只负责冻结有界上下文、
启动异步判断和恢复到期批次，没有第二个 Agent 或工具循环。每个话题同时最多一个中间请求；
网络调用不占用主回合锁，也不阻塞其他话题的调度。

新消息、去重和待判状态同事务保存；决定、判断水位与主唤醒候选也同事务提交。
判断水位独立于主模型 read/seen。已展示给运行中或已完成回合的消息不重复制造回合，未展示的新消息继续入池。
快照保留版本、水位、摘要长度和原文指纹，重试恢复相同输入，不另存一份完整聊天。
暂停、角色/配置变更、消息编辑或来源删除使旧判断失效；超时和坏输出采用原有的有界重试及一次降级。

schema 9→10 增加消息资格事实、待判时间和批次到主回合的关联。
既有消息只用作历史上下文，不在升级时重放；主 read/seen、记忆和角色文件保留。
旧 schema 的镜像回滚需要同时恢复发布前数据备份。

## 等待、回复与主动机会

最近已确认发送的 Bot 发言作为上下文，包括接收用户回答早于本地发送回执的竞态。
论坛话题根引用单独标记，不再当作正在回答创建话题的人；真实回复对象仍提供给模型。

定时续接继续执行主模型已经提出的明确意图，不重复请求语义批准。
新消息是否满足等待、是否打断潜水统一交给中间模型；满足一次性条件时返回 `fulfills_intent=true`，
只有实际接纳或已经展示该消息才消耗相同条件，排队期间仍受原条件 TTL 限制。
无关的新呼叫可以打断等待，但不能冒充已满足原条件。
睡前观察到期无新内容仍在本地结束；有新内容按普通合并窗口进入判断。

主动机会沿用来源、期限、quietHours 和去重检查，再交同一个中间模型判断。
记忆候选提供来源 ID、revision 和最多 1000 字摘要，模型无需根据编号猜测内容。
已有待判消息或主回合时暂缓主动机会。observe 本身不安排周期复查，无新内容/机会/明确续接时不调用模型。

## 配置兼容

| 原配置或能力 | V3-B 效果 |
| --- | --- |
| `nicknames`、Bot 身份、真实回复 | 作为模型事实，不直接触发 |
| `wakeKeywords`、`wakeSenders`、`wakeOnQuestion`、`wakeOnMessages` | 作为等待/参与意图，不再执行本地语言匹配 |
| 临时 `social_set_wake` 条件、TTL、one-shot | 交中间模型解释，代码执行到期及一次性消耗 |
| `sleepInterrupts` | 提供给模型的潜水中断意图 |
| `wakeProbability` | 旧 JSON 可读但不再抽样；工具拒绝设置非零概率 |
| `replyAttention`、未完成句/紧急词窗口 | 不再参与语义准入；旧字段兼容保留，后续 V3-C 清理展示 |
| 固定 coalesce、总等待上限、预算、发送重试 | 继续由代码执行 |
| 有限/无限等待、绝对期限、主动来源 | 保留原可见能力并整合统一判断 |

中间输出协议 `social-judge-v2` 为 decision、through_seq、source_seqs、reason 和 fulfills_intent。
判断记录与主快照提供决定、理由和来源；不记录凭据或详细思维链。

## 独立 OAuth

使用 `openai_codex` / `openai-codex/gpt-6-luna`，low，512 输出 Token、15 秒超时、至多一次重试。
全局中间请求上限 240/小时，降级意图上限 6/小时；主模型原有额度另外执行。

已通过用户独立登录，为 Bot 创建单独的 OAuth session 和 refresh token。
凭据保存在实例数据 `telegram-social/oauth/auth/codex.json`，不放进 Git 或镜像。
网关默认将中间模型 OAuth 根目录解析为实例的 `telegram-social/oauth`，
可用 `judge.oauthStorageDir` 明确覆盖；容器中实际为 `/data/telegram-social/oauth`。
该存储关闭自动导入本机 Codex CLI 凭据。普通 Codex provider 仍使用原默认认证路径。
已实际验证刷新成功并轮换 Bot refresh token，现有 CLI 登录文件指纹未变、两者 session 独立。

## 验证与发布

确定性回归验证完整消息准入、模型 observe 不被 @ 绕过、批次总期限、话题根、忙时投递、
接收/发送竞态、原子失败、重启、暂停、隔离、等待和共享工具。旧语义规则专属测试已移除或改为模型结果驱动的集成测试。
provider 测试覆盖独立持久存储和默认路径，发布管线同时运行 Codex provider/OAuth 回归。

真实 `gpt-6-luna` 使用独立 OAuth 运行 9 个合成端到端样例，9/9 符合预期：
“肥鱼呢”（含话题根）、“肥鱼在吗”、无称呼连续提问、“下午三点”回答 Bot、
群友互聊、引用旧名字、潜水时点名、相似人名、“快出发咯”承接出发请求。
第一轮普通回答出现 1 次漏判；补充 is_self 和短回答语境说明后再次运行全部样例通过。
最终单例约 1.9–9.0 秒、1077–1204 总 Token；这些样例不能保证真实群聊零漏判或误判。
验证未运行 Telegram 接收者或向真实群发测试消息，也未确认主 read。

完整 release、实例数据核对、镜像内验证及实际版本在发布完成后补记。
