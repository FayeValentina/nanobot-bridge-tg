# 群回复可靠性修复

2026-10-29 对实际群使用记录核对后，修复以下行为；整群仿真、主动机会与共用工具权限继续保留。

## 漏掉显式发送

仿真最终文本仍是内部内容。搜索后直接写出最终答案、没有显式发送时，运行钩子请求一次额外的模型迭代，
让模型选择调用 social_send/message，或选择空输出/social_wait。不会直接公开最终正文、内部笔记或推理。
已有当前对话发送尝试、显式等待、空输出和模型错误不会触发该检查；最多检查一次且服从原迭代上限。
仍不发送且再次写内部正文时，唤醒记录为 unsent，便于排查。配置 repairUnsentFinal 默认 true，可关闭。
Runner 仅增加供 hook 请求后续迭代的 continue_turn 字段，投递选择仍由 Telegram 通道钩子负责。

## 条件等待与临时状态

关键词/发言者条件且 on_messages=false 时，普通新消息只观察，不打断 waiting；真实 @/回复及昵称仍可打断。
普通未设置条件的 waiting 继续关注新消息。sleeping 继续忽略普通事件，潜水语义不变。
social_set_wake 新增 ttl_seconds（默认 3600 秒，受 maxWaitSeconds 限制）与 one_shot（默认 true）。
条件在模型认领匹配唤醒时消费，不因排队提前消费；候选也不能超过条件截止时间。
过期条件在读取状态或观察消息时清除，不后台调用模型。无条件调用 social_set_wake 可主动清空。
临时游戏可设置包含取消词的条件；协议要求任务结束后清空条件。

## 已读水位

成功结束/静默/等待的回合自动确认该回合实际展示过的连续消息前缀，复用原 exposure 证据和 mark_read 校验。
失败或未解决的 unsent 回合不推进；不确认新到消息、不跨越未展示缺口、不影响其他话题。
仍可显式 social_mark_read。聊天和原始历史保留。

## 普通 message 的平台回执

MessageBus 为显式消息工具增加通道提供的 confirmed sender。Telegram 启动后注册该发送能力，
直接等待普通文本/附件的 Bot API 结果，保留私聊、话题、跨群与后台发送能力，不受 social 发送预算约束。
文本在明确的 HTML 解析拒绝时可降级纯文本；网络超时为 unknown，不自动重发非幂等发送。
已确认的分段/附件返回 message_ids 前缀，后续失败不会把已发送部分说成没发送。
其他未提供回执能力的通道或自定义回调返回 queued，明确入队不代表平台确认。

工具结果使用结构化 queued/sent/failed/unknown。当前群普通发送的回执保存于 social 库 message_deliveries，
确认的普通文本同时进入群观察历史；不额外计入 social_send 的额度。平台请求前先登记待确认回执，
重启将未完成回执标为 unknown，并取消对应旧回合的自动重放。平台已确认但日志落盘失败时记录错误，
仍保留已确认状态，避免因日志问题诱发重发。schema 5→6 只新增回执表和索引，原消息、水位、记忆保留。
旧版本回滚需要恢复与旧代码对应的数据备份。

## 本机配置与验证

本机 social 的 maxRequestsPerHour 已设为 120（唤醒回合），maxSendsPerHour 设为 60（social 发送尝试），
其配置位置为 channels.telegram.social；不把 social 额度称为所有工具的统一总上限。
allTopics、肥鱼昵称、主动机会开启和 quietHours 关闭继续沿用。

定向验收覆盖一次补发确认、显式沉默、原文不外泄、已读缺口与忙时新消息、条件过滤/认领/过期/重启、
普通文本与附件的真实回执替身、超时不重试、部分发送失败、跨群/私聊权限、入队语义及 schema 升级。
不向实际群发送测试消息，不调用真实模型验证。发布版本、完整检查和实例核对结果见本机管线说明。
