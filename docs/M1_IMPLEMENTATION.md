# M1：可观察且隔离的文字群友

> 用户后续要求共用普通工具权限。本页早期的白名单、不可编辑角色与私人资料/记忆隔离
> 已撤回，当前以 [共用工具权限约定](SHARED_TOOL_PERMISSIONS.md) 为准。

> 本文保留 M1 阶段的实现与验收记录；后续等待/潜水、合并调度、冷却及发送动作扩展见
> [M2 实现说明](M2_IMPLEMENTATION.md)。当前行为以两阶段实现和最新迁移计划为准。

M1 在现有 Telegram 通道中增加默认关闭的文字群仿真。普通群消息只被观察，
@ 或回复机器人可唤醒模型。人格、会话、观察记录和工具权限按群/话题隔离。
2026-10-28 已完成源码与离线验收，尚未提交或部署。
本阶段不包括等待/潜水调度、主动插话、媒体下载理解、群记忆自动学习或专用管理面板。

## 配置与角色

配置使用 `channels.telegram.social`，可通过配置文件或现有 Telegram 设置页的
“群友仿真”JSON 字段修改。配置经过同一 Pydantic 契约验证；未知字段、重复授权、
非法角色名、非负群号及非法观察成员均被拒绝。所有语言已有该字段的标签。

示例群号仅作说明，不能直接用来开启真实群：

```json
{
  "enabled": false,
  "scopes": [
    {
      "chatId": -1001234567890,
      "threadId": 42,
      "roleId": "guest",
      "background": "这是一个朋友交流日常的群。",
      "enabled": true,
      "observeFrom": ["*"]
    }
  ],
  "snapshotMessages": 30,
  "snapshotChars": 12000,
  "retentionMessages": 500,
  "maxRequestsPerHour": 12,
  "maxSendsPerHour": 6,
  "maxTextChars": 2000
}
```

每条 scope 精确授权一个群/话题。`threadId: 0` 表示无话题会话；它不授权所有话题。
话题 42 的授权不自动允许话题 43。会话键继续使用 `telegram:<chat_id>` 或
`telegram:<chat_id>:topic:<thread_id>`，存储同时包含通道实例标识。

角色放在 `<config-dir>/telegram-social/roles/<roleId>.md`，文件不能为空，最大
32000 字节，解析后的路径必须仍在角色目录内。角色和 background 都由操作者管理；
群成员的称呼、备注和提示词不能赋予管理权。

生产数据根是容器内 `/data`，宿主对应既有部署的 `shared/data/`。例如 guest 角色应位于
`/data/telegram-social/roles/guest.md`。源码目录不保存真实角色、群资料、数据库或凭据。
独立验证实例使用自己的数据根与测试 Bot，不能与生产同时轮询同一 Token。

`observeFrom` 是该 scope 的观察权限，与原 `allowFrom` 和私聊配对策略独立。
这里的 `*` 只授权观察已明确批准的这个群/话题，不会开放普通私聊、管理命令或全局工具。
匿名/以频道身份发言、缺少稳定用户身份的消息在 M1 明确跳过；Bot 消息可记录但不唤醒。
普通消息必须先由 Telegram 送达这个 Bot，应用无法补取未收到的任意群历史。

## 消息、快照与水位

`social.sqlite3` 使用标准库 SQLite、WAL、小事务和 schema 版本 1，只有一个进程内所有者。
消息按 scope 递增 seq，记录 update/message ID、稳定成员 ID、显示名、时间、引用 ID、
媒体类型和 is_self。重复更新不重复记录或唤醒；编辑修订现有记录，不另开模型回合。

普通消息不产生模型请求、不下载媒体、不启动输入状态或公开内部通知。
媒体在 M1 只显示类型标记，模型不能据此声称看到了图片。引用发送只允许本 scope
已经缓存的消息 ID，引用不可用时失败，不改发默认话题。

快照提供当前时间、相对年龄和有界消息资料。未读优先从最旧的未读开始，必要时带上
触发消息。长消息有截断，历史清理造成的缺口会以 history_gap 明确展示。
若有最近的未知发送结果，快照会附上有界的 uncertain_send，提醒模型不要重复该次文字。

`read_through` 仅由显式工具确认。新增的 `AgentHookContext.model_messages` 提供该次
真正送入 provider 的消息投影；曝光 hook 只认出完整保留的快照。调用工具返回一页数据
还不等于展示给模型，必须等下一次模型请求带上该页，才能确认其中的连续 seq。
读取授权绑定当前 turn、scope 和角色版本；旧回合、其他群或被截断掉的快照都不能授权已读。
确认旧快照不会清除新到消息。被清理掉且未读的缺口不会伪装成已读；M1 不自动跨越缺口。

消息、视图、更新去重记录和任务日志都有保留上限/期限。写入失败会回滚 seq 与去重更新；
损坏数据库或未知 schema 不会被静默替换为空库。

## 人格和记忆隔离

通用 `SessionPolicy` 独立控制持久化、个人资料、长期记忆、技能、全局记忆归档、命令和工具。
M1 群回合保留 JSONL、会话内历史与压缩，但不加载个人 AGENTS/SOUL/USER、长期记忆、
自动/显式私人技能或全局运行时资料提供器。

可信人格通过 ContextBuilder 的可选参数装配；首次构建、续轮、压缩重建和空闲压缩
使用同一策略。普通私聊仍使用原人格、技能和记忆路径。

正常摘要、provider compaction 和原始归档降级都受独立的 archive_memory 策略控制。
群摘要只进入当前会话，不写共享 history.jsonl，也不进入个人 Dream 的处理输入。
角色切换后不重放旧人格的摘要、压缩缓存和模型续接状态。
压缩请求和 token 估算也只使用该会话白名单内的工具描述。

持久化的 `_isolated_context` 是隔离标签，不保存可放宽权限的运行时策略。
会话加载、token 估算和空闲归档都会重新解析可信绑定。缺失运行时、角色不可读或
角色越界时默认拒绝执行/全局归档，不能回退个人策略。

首次采用仿真或切换角色时，旧记录仍保留在 JSONL 中，新的回放边界移到旧历史之后，
避免把启用前的个人上下文或旧角色摘要带进新回合。观察库中的群消息仍属于同一个群。
进程重启后保留已提交历史，清除不透明的在途 provider 状态和恢复检查点，避免续接旧工具动作。

## 受限工具和发送

M1 只授权以下四个工具：

| 工具 | 行为 |
| --- | --- |
| social_get_state | 查看当前 scope 的水位、最新 seq 和预算上限 |
| social_read_messages | 有界读取当前 scope 的未读/近期消息 |
| social_mark_read | 确认本回合真正展示过的连续水位 |
| social_send | 向当前 scope 发送一段短文字，可引用本 scope 已观察的消息 |

这四个工具必须被会话白名单显式授权；注册到共享 registry 不会让个人/临时会话自动获得它们。
群回合不提供通用 message、文件、命令、会话读取、MCP、cron 或子代理工具。
模型强行调用未授权名称或传入额外目标群参数也会失败。
个人心跳不会自动选择仿真群为投递目标；替代会话键也不能向已开启的仿真话题执行私人上下文。

所有 social 工具校验 RequestContext、当前群/话题、活跃唤醒任务、配置版本和权限。
群内 `/new`、`/dream`、`/help` 等被视为聊天资料，不执行实例管理操作。
群聊没有角色文件修改工具；角色与授权配置只能由操作者或经过认证的现有管理入口修改。

仿真回合采用显式工具发送。内部最终文字、空回复兜底、工具提示、思考流、压缩通知、
模型错误和 dispatch 异常都不作为群消息发送。空最终回复正常结束，不额外调用模型索取答案。
Telegram 通道还在普通 send/send_delta 出口检查当前 scope，阻止配置切换前的旧流继续输出。

发送在调用 API 前重新校验授权、角色版本、时效和预算，串行保留同 scope 的发送顺序。
action 先持久化 sending，收到 Telegram message_id 才推进 sent，并将 Bot 发言加入观察库。
超时/断网结果不明确时记 unknown 且不重试；平台明确拒绝记 failed。所有尝试都计入小时预算，
失败或未知结果不能通过重复调用绕过预算。重启时遗留 sending 同样成为 unknown，不自动重发。
同版本、同文字的 unknown 动作在 24 小时内也不能通过新 action 盲目重复。
M1 不做自动 429 重排、分条突发或完整的行为调度，这些属于 M2。

## 唤醒、配置变化与恢复

SQLite WakeJob 是唯一持久唤醒队列，MessageBus 只负责进程内运输，不再建立一份
LocalTriggerStore 队列。M1 提供 @/回复事件唤醒与必要的恢复，不运行定时主动参与循环。
唤醒窗口为 120 秒，并受每 scope 的模型请求次数限制；超限消息仍保留为未读。

执行复用现有 AgentLoop 会话锁与 pending queue。忙时新到的唤醒可进入当前回合的
后续输入，曝光 hook 将实际展示的关联任务归到本回合完成，未读不会被自动清除。
重启只恢复每 scope 最新的一个未过期唤醒，取消其他旧任务；若旧问题后已有发送结果不明，
也不恢复该问题的自动唤醒，避免重新生成同一答复。恢复在接收新更新前完成。同一进程的 Telegram 重连
不会反复恢复或认领任务。

修改角色、背景、观察权限、全局预算或撤销 scope 会使旧版本任务失效。关闭 social 后不再观察或
投递仿真唤醒，普通入站按现有 Telegram 过滤配置恢复。曾用于 social 的会话仍保持
资料/归档隔离，并以无全局工具的普通文字模式回复，避免历史群资料混入个人记忆。
从未启用 social 的群、未授权话题和私聊保持原有行为。
