# V4-C：主动交流体验验收与收敛

2026-10-31，V4-C 已完成实现、语义验收、本机发布和安装包核验，V4-A/B/C 均已完成。
V4-A/B 的调度、事项记忆和回执机制保留；本批无数据库迁移，schema 13，V3 仍为 social-judge-v6。
主 Agent 可信协议更新为版本 4。

## 行为收敛与验收入口

新增可重复运行的 `nanobot.channels.telegram.tests.evaluate_social_v4`。
使用既有 SocialScheduler/wakes、真实 V3、ContextBuilder、AgentRunner 和 social 暴露/收尾 hook，
不手工把一个普通快照改成 idle。冷场测试用可控时钟和抽样值 0，验证无新消息/已读资料仍能走定时队列；
不实际等 90 分钟。模型使用实例配置，合成角色、消息、SQLite 与发送替身全部在临时目录。
只有显式 `--live-web` 的搜索场景使用现有真实网页工具，不启动 Telegram 接收者、不向真实群发探测消息。

入口保留输入、公开文本、原生发送 ID/结果、事项与尝试状态、模型调用数/Token/延迟和网页查询/来源，
不保存凭据、真实群对话副本、详细思维链或自建哈希。
每个场景有结构检查；具体相关性、重复/不合适追问与自然度需另行阅读实际输出，不能用自动通过代替语义复核。
测试工具集合只服务于合成验收，不改变 social 与普通助手共用工具/MCP/技能/记忆/后台权限的运行策略。

```bash
.venv/bin/python -m nanobot.channels.telegram.tests.evaluate_social_v4 \
  --config <实例配置路径> --output <报告路径> --live-web
```

普通发言继续鼓励具体好奇；补充仅依据已展示消息、实时记忆和已核实来源发言的约束。
自己的 pendingThought/motivation 是想法而非真实收拾行李、旅行等生活经历，不为自然聊天编造经历；
出发时刻也不自动证明当地天气。样例引导用具体问题接话，不要求每条正常答复都带问号。

冷场搜索建议一次聚焦查询，必要时核对具体文章，每次机会总计至多三次网页查询的软提示。
避免反复打开门户/导航或扩大重复抓取；若只看见标题/摘要，仅分享其支持的事实并说明来源。
搜索失败或工具不可用时安静结束本次机会，不向成员播报工具故障、不让成员代查、
不把失败查询存成紧急主动意图；后续独立周期仍可再考虑。
这个三次提示用于 idle 探索，不限制成员主动要求的普通研究任务，也未新增 social 专用工具权限门槛。
现有主迭代上限仍是执行边界；验收中另用三次网页工具预算防止外部查询失控，并记录超预算尝试。

## 实际模型语义验收

主模型 deepseek-flash，temperature=0.1、reasoning_effort=null；合成验收 max_tokens=4096。
中间模型 openai-codex/gpt-6-luna，low，沿用实例独立 OAuth。

| 场景 | 实际结果与复核 |
| --- | --- |
| 无消息、无记忆冷场 | 直接进入一次主回合、V3 零调用；自然内容不足时保持沉默，无公开兜底句 |
| 已读资料中的待追问 | 冷场主动问“明天郊游定好几点出发没？跟谁一起呀”，关联原事项并确认一次尝试 |
| 待说想法/动机 | 围绕轻装出门问“三样必带”，表达为想法，没有捏造真实行程 |
| 旧事接续 | 问昨天陶艺课体验和做出来的东西，没有重讲课程介绍 |
| 普通陈述 | V3 将“明天要出去玩”交主 Agent，主模型自然问“明天去哪儿玩呀？” |
| 无点名短回复 | “下午三点，跟朋友一起”由真实 V3 承接，继续问目的地；原事项标为回应，旧主动计数不增加 |
| 无回复 | 普通等待超时本地结束；后续独立冷场周期仍能进入主回合，不每 30 秒调用模型 |
| 两次无人回应 | 持久次数保持 2、事项 dropped；没有第三次追问 |
| 明确结束 | 放下事项，简短确认后不继续追问 |
| 明确要安静 | 主模型应用意图，不公开回复 |
| 仅有兴趣、没有待说内容 | 实际读取 NASA 官网并查询官方天文消息，基于官方来源分享并问看法 |
| 搜索失败 | 有限尝试后沉默，无工具故障播报、无催查循环 |
| 搜索不可用 | 没有伪造新消息，保持沉默 |
| 重启后的待说想法 | 原 ID/动机/次数保持，冷场仍能分享并关联发送 |
| 压缩后的待说想法 | 沿用上下文摘要重建路径与当前消息尾部，可信主动协议保留，实时记忆仍能注入并关联发送 |

最终完整 15 例结构检查通过，逐条发言已复核。40 次主模型 + 4 次中间模型调用，
主模型 306,309 tokens，中间模型 6,185 tokens，合计 312,494 tokens。
主回合阶段约 2.8–9.7 秒（含网页工具/发送替身），中间模型约 1.5–2.5 秒。
这些是整轮评估的 Token，包含每次重放上下文；不等于公开发言条数，也不是常驻每小时成本或费用报价。

另补强“已确认发送后无人回应”探针：从一条已确认的替身发送建立真实自动接话等待，
到期新增主模型调用为 0；后续独立周期可达主回合。该探针 3 次主调用、22,924 tokens，
后续冷场主模型选择沉默，不把 completed 记为主动发言。

联网例使用现有网页工具；分享的土星南极十边形话题已与
[NASA 官方稿](https://science.nasa.gov/missions/hubble/nasas-hubble-tracks-new-decagon-encircling-saturns-south-pole/)和
[ESA/Hubble 官方稿](https://esahubble.org/news/heic2612/)核对。
这是来源明确的 2026-09-02 消息，不宣称当天新发现。

调优探针曾出现无依据天气判断、将想法写成最近生活经历、搜索失败后播报故障和重复抓取。
本批按这些实际输出收敛提示。提示不能保证模型始终严格遵循，保留为后续真实使用反馈项；
不引入文本相似度判定或第二个模型审查每条回复。

## 旧字段与保留差异

| 字段/范围 | 当前契约 |
| --- | --- |
| intervalSeconds | 兼容读取、给出废弃提示后丢弃；不能覆盖 1800–5400 秒随机范围 |
| requireContext / contextMaxAgeSeconds | 仅约束旧来源候选，不能关闭 V4 idle 周期 |
| wakeProbability / sleepInterrupts.probability | 旧配置兼容项，不恢复普通成员消息的本地概率准入 |
| wakeOnQuestion / 关键词/成员偏好 | 作为 V3 participation 资料，不把普通接话等待伪造成只等问题 |
| replyAttention、dynamicWait.enabled/unfinishedSeconds | 原兼容项，公开默认契约已退役；新成员由 V3 统一判断 |

与 qq-bridge 保留的适配差异：消息仍经过 V3；定时 idle 直接交既有主 Agent；
答后使用释放锁的后台等待；两次上限按稳定事项 ID 与平台确认持久计数；普通工具权限共用。
未关联自由文本的语义重复仍需模型正确处理，不宣称存在任意改写语义去重。

本人实例启用 30–90 分钟随机检查、15 分钟空闲、基础概率 0.3，Asia/Tokyo；
近期发送 ×0.5、夜间 ×0.3、小时内至少五条 ×0.3、有效待说想法先 ×1.4 并封顶。
quietHours 保持关闭，主唤醒/发送尝试额度每小时 120/60；模型、OAuth、角色、群范围和原配置保留。

V4 覆盖 V2-C 的必要统计/主动调度和 V2-E 的待追问/想法动机；不另开同一批次重复开发。
V2-D 的查询/分条/反馈、V2-E 的黑话/画像扩展、V2-F 的媒体表达仍待后续重评，M5 继续暂缓。
