## 1. 用户目标与完成口径

希望 Agent 主动推动交流、对用户产生具体好奇、询问近况和接续之前的事情，改变一问一答后立即结束的体验。
本轮以本地 qq-bridge 的 `reserved2 / socialV2` 为行为参考，交付以下四项，不能只提高唤醒频率：

1. **冷场也能自己醒来**：默认每 30–90 分钟随机检查，安静至少 15 分钟后按概率产生主动机会；
   不要求有新消息、未读消息或尚未消费的记忆。
2. **明确鼓励主动交流**：每次唤醒提醒不要习惯性潜水；主动机会优先开话题、追问未聊完的事、分享想法；
   一时没有想法时可搜索与群友兴趣相关的新内容。
3. **保存未完成的交流**：话题保存 `pendingQuestion`；待说想法保存 `pendingThought` 与 `motivation`；
   后续回合能够重新看到、自然接续，也能完成、过期和放下。
4. **调整分寸、保持连续**：有待说想法提高主动概率，近期说过很多则降低；回复后保持接话意图；
   同一件事主动发起/追问最多两次，无人接或话题已漂移就放下。

“有定时器”“有主动候选”或“主回合 completed”均不等于已经实现主动交流。
完成需分别证明定时调度可达、主模型有正确输入与策略、待跟进资料可用、真实发送可追溯，
并用实际模型的合成对话检验主动提问和连续交流。有限样例通过不承诺每次都发言或始终自然。

qq-bridge 默认配置和示例配置的基础概率均为 **0.3**；调度函数在该值缺失时另有 0.4 兜底。

V4 按用户目标允许自然的问题开头，重点检验具体追问，不机械要求每条消息以问题结尾。
搜索产生的话题要如实说明来源，不把搜索结果写成自己真实经历或伪造刚发生的生活。

## 3. 与 V3、现有调度和权限的衔接

### 3.1 新消息判断与自主冷场机会

**获准的新成员消息仍全部经过 V3 中间模型。** 不恢复昵称/问句正则或普通消息概率准入。

**V4 冷场周期机会按 qq-bridge 直接交主 Agent。** 它是已配置的定时自主事件，
无需先让中间模型在没有新内容时判断“是否有话可说”；主 Agent 才能查看记忆、搜索、形成想法和决定是否开口。
这明确调整 V3“所有主动候选先经中间模型”以及 M4“等待/潜水一律跳过主动机会”的旧范围，
不把周期事件伪装成新成员消息，也不建设第二个 Agent 或另一套消息语义通道。
现有消息/记忆来源候选继续遵循自己的有效性规则；如需合并，关联来源，不能重复投递一个主回合。

流程：本地周期检查 → 空闲/概率/额度与状态校验 → 既有 wakes 队列 → 既有主回合 →
读取待跟进资料/必要时搜索 → 主动发送或沉默 → 平台回执与跟进状态更新。

- 复用 `SocialStore`、`SocialScheduler`、会话锁及现有主模型入口；业务留在 Telegram social/工具边缘。
- 周期事件用现有记录 ID 和明确机会序号/修订号识别；允许没有新消息 seq，不伪造触发消息或推进已读。
- 同一 scope 同时至多一个主执行。新消息判断或主回合正在进行时，本次主动机会跳过，按下次随机期限检查；
  明确点名与尚未认领机会竞争时优先消息回合，关联/取消机会，不额外发送一轮。
- 普通 observing/sleeping 不是关闭自主机会的开关。有效显式等待期间延后冷场机会，不消费或满足该等待；
  等待到期/取消后恢复。用户明确要求停止主动联系的意图也必须保留，不能因切回普通潜水就重新启用。
- 暂停、撤权、关闭主动功能、quietHours、时效、请求/发送预算仍生效；quietHours 继续只管主动机会。
- 群/话题分别统计空闲、保存记忆和发送。allTopics 仅覆盖已建立的有效 scope，不凭空为所有未见话题制造定时器。
- 普通助手和 social 的工具、技能、MCP、共享记忆、后台/跨会话权限保持相同；不新增 social 工具白名单。
- 不新增哈希/指纹；沿用消息 ID、记忆 ID、机会 ID、revision 与源值比较。无需新常驻服务或外部数据库。

### 3.2 模型调用边界

未到期、未达到空闲阈值、概率未命中、忙碌、暂停、quiet 或已知额度不足的检查均本地完成，不调用模型。
命中的有效周期机会允许在没有新消息/新记忆时产生一次主回合，这是 V4 刻意恢复的成本与行为。
主模型沉默后不立即再问一次，不生成“确认你是否想说话”的循环；仅按下一随机周期重新评估。
V3 的正常消息判断、明确等待的期限续接及有限故障重试继续沿用既有边界。

## 4. 冷场周期、概率与配置迁移

### 4.1 默认策略

| 参数 / 修正 | V4 目标 |
| --- | --- |
| 随机检查间隔 | 30–90 分钟，等概率抽取一次下次期限 |
| 空闲阈值 | 距最后一条有效成员消息至少 15 分钟；编辑/重复更新及 Bot 自身发言不重置成员来信时间 |
| 基础概率 | 0.3，配置合法范围 0–1，0/1 必须按原值生效 |
| 有有效 pendingThought | 基础概率 ×1.4，上限 1 |
| 距最近确认公开发送不足 30 分钟 | ×0.5 |
| 当地 23:00–08:00 | ×0.3；使用明确配置的 IANA 时区，quietHours 开启时仍直接跳过 |
| 近 1 小时自己确认发言至少 5 条 | ×0.3 |

按表中顺序计算修正，给出最终概率与命中结果。pendingThought 必须仍未完成/放下/过期且可主动尝试，
已经说完或达到两次上限的条目不能持续加权。短时间分条按真实消息计数还原原版，并另展示发言组数，避免误解。
普通 message 和 social_send 的已确认发送都计入；queued/failed/unknown 不计作成功发言。
统计窗口资料不足时明确标注，不把缺失历史当成零。

下次期限、当前机会序号、抽样结果及消耗状态持久化；重启不重新掷同一次骰子，不集中补发停机期间的机会。
错过有效窗口时只登记 missed，生成下一随机期限。一次失败或沉默不能无限重试同一机会。

### 4.2 配置契约与本人实例

在既有 scope.proactive 下声明随机区间、空闲阈值、基础概率、时区和上述修正参数；
schema、manifest 和现有 JSON 编辑入口同步。最终字段名在 V4-A 冻结并记录迁移映射。

- 保留 proactive.enabled 为总开关，软件默认不替新用户开启 social；本人实例已开启的范围保持开启。
- V4 本人实例目标预设明确切换为 30–90 分钟、15 分钟、0.3 及无新内容也可产生的周期机会。
  这是未来实施批次的配置变更，本次写计划不修改实际配置。
- 旧 intervalSeconds 从固定周期入口退役，映射和废弃提示需明确；不能让旧 1800 秒暗中覆盖新随机区间。
- 旧 requireContext 不再限制 V4 冷场周期事件。它对旧来源候选的含义保留说明，不保留一个能悄悄禁用本轮目标的默认门槛。
- 原 ttlSeconds 继续限制本次机会时效，contextMaxAgeSeconds 只限制引用旧消息的相关性，不使整个冷场事件无效。
- 不暗改模型、OAuth、角色、群范围、既有额度或 quietHours；新时区/行为预设在实施发布记录中写清。

## 5. 主动表达与答后连续性

每次主回合的当前可信协议都包含简短主动性引导：有具体好奇、观点或与对方近况相关的内容就自然开口，
不要习惯性潜水，不必等下一次提问才继续交流。普通唤醒也应能从用户一句近况中提出具体问题。
角色、重启与上下文压缩后保持该行为提示；不要求模型反复读取相同 prompt。

冷场机会单独说明“这是可以主动发起交流的时机”，提供以下选择：

1. 接续仍值得关心的事情，提出具体待追问问题；例如旅行结束后问实际体验，而非重复介绍目的地。
2. 表达仍想说的想法及其自然来由，或结合群友已知兴趣开启新话题。
3. 没有现成话题时可用现有搜索/网页工具找相关新内容，判断后简短分享或询问看法。
4. 确实没有自然内容、对方已结束或不想继续时沉默，并正确结束回合。

搜索沿用普通工具与现有迭代上限，每次机会只做有限探索；工具未启用或失败时可直接沉默，
不为主动性安装新服务，不把强制联网或每轮必问当成协议。

确认发送后鼓励继续接话，复用 `social_wait(purpose="messages")` 和后台续接：普通等待参考 30 秒，
需要时可在现有限制内延长。等待释放会话锁，不照搬 qq-bridge 的长轮询占锁方式。
用户在期间回复，无需再次点名，应由 V3 识别承接并交主模型；明确等待某人/内容的选择性仍有效。
无回复时本地结束观察或转普通潜水，不为了“继续聊”每 30 秒调用一次模型。
后续独立冷场周期仍可提供新机会，不能把一次等待超时等同于永久关闭主动性。

## 6. 待追问、待说想法与两次上限

扩展现有 `social_memory` 与有来源的 topic/pending 记忆，不建并行人格库或无来源成员画像。
原 ID、证据、确认/纠错/删除、TTL 和群/话题隔离继续生效；内容与动机都是资料，不是系统指令。

| 对象 | 必要字段及用途 |
| --- | --- |
| 进行中话题 | 原 topic ID/content，相关成员 ID，`pendingQuestion`，最近提及/适宜跟进时间，状态 |
| 待说想法 | 原 pending ID，`pendingThought` 文本，`motivation`（如好奇/关心/分享），创建/过期时间，状态 |
| 跟进记录 | 关联稳定话题/事项 ID、机会/回合 ID、已确认主动发起次数、发送结果、最后尝试及对方回应状态 |

成员说过的计划/偏好关联真实消息证据；Agent 自己产生的问题、想法和动机明确标为自身意图，关联产生回合，
不能伪造成群友事实。待跟进时间是适宜时机，不承诺提供本轮之外的精确定时提醒系统。

每次相关主唤醒有界展示进行中话题、待追问、待说想法/动机、最近互动及尝试次数；
可用现有查询工具取得完整条目。所需摘要也可供 V3 判断用户短回复是否承接，限制长度，不复制整份历史。
完成、取消、纠错、删除和过期后，旧提示、候选及后续发送不得继续使用失效条目。

**同一件事的主动发起/追问最多两次**，跨机会、跨重启保持，具体定义如下：

- 按稳定话题/跟进事项 ID 计数，一次分条发送组最多算一次。仅确认公开发送才增加成功次数；
  调度、observe、主模型沉默和工具失败不冒充已问过。
- unknown 保留未决尝试并占用一次可尝试名额，未核清前不自动重发；发送确认、计数和后续状态可幂等恢复。
- 模型在发送主动追问/分享时关联事项 ID；工具检查次数并返回明确剩余额度。普通 message 路径也须能关联确认，
  不能只给 social_send 计数而遗漏普通工具；这不是新的 social 工具权限限制。
- 改写文字、改标题或普通 revision 更新不自动清零，相关改写应沿用原事项；不得用内容哈希认定同一件事。
- 无人回应可在后续合适机会再尝试一次；两次仍无人接就置为放下，不再加权或出现在待追问建议中。
  话题明显漂移、明确拒绝/结束时可提前放下，由模型记录语义判断，不新增取消词表。
- 用户主动回应后进入正常对话，回答不受“两次”限制；若产生新的未完成事项，应明确新事项与新证据，
  不能靠自动重置旧计数反复催同一问题。普通用户问题答复不受主动次数限制。

qq-bridge 的两次上限主要写在提示词里；V4 在保留模型语义选择的基础上增加最小的持久计数与工具校验，
并通过实际模型样例检验事项关联。该计数不宣称能识别任意未关联自由文本的语义重复。

配置、角色、普通历史、主 seen/read、记忆及证据按源值直接核对保留。

## 8. 验收矩阵

| 场景 | 必须验证的结果 |
| --- | --- |
| 没有未读，记忆全已考虑，冷场超过 15 分钟 | 可控随机命中后产生一次主回合，不被 requireContext 或记忆版本卡住 |
| 普通潜水 / 显式等待 / 停止主动联系 | 普通潜水可产生冷场机会；有效显式等待延后且不被假满足；停止主动联系不被定时器绕过 |
| 间隔、空闲和概率 | 30/90 分钟边界、15 分钟边界、概率 0/1、各乘数及顺序正确；配置缺失默认 0.3 |
| 冷场唤醒的内容 | 提示鼓励开话题、具体追问/分享；没有原消息也能形成内容，不捏造旧消息或个人经历 |
| 普通聊天主动提问 | 给出“明天要出去玩”等完整陈述后，模型能提出贴合语境的具体问题；不依赖问号或下一次用户提问 |
| 待追问与动机 | 建立、修改、重启后读取、摘要注入、完成/删除/过期均有效；自身想法不冒充用户事实 |
| 回复后接续 | Bot 提问后用户只回“下午三点/跟朋友”，无需点名即可接续；无人回复不每 30 秒叫模型 |
| 两次上限 | 跨周期/重启、改写、分条和普通 message 仍正确关联；两次无人接后放下；failed/unknown 分别处理 |
| 无待说内容但有兴趣信息 | Agent 可有限搜索后开启新话题；搜索不可用/失败可沉默，无重试调用链 |
| 模型沉默或未命中 | 不公开兜底句，不立即重新唤醒；下一随机周期仍正常存在 |
| 新消息与主动竞争 | 点名优先，忙时跳过，既有消息候选不重复形成第二主回合；新到未展示消息不被标读 |
| quiet/预算/暂停/变更/恢复 | 原约束有效，普通工具权限不变；过期机会不补发，抽样和认领不重复 |
| 多话题与上下文压缩 | 各 scope 的时钟/事项/计数不串线；压缩后保留主动引导，不恢复已放下事项 |
| 升级与回滚 | 原配置/角色/消息/水位/记忆证据保留，失败事务回滚，版本与对应数据可恢复，无自建哈希 |

确定性测试采用可控时钟、可注入随机源、临时 SQLite 与模型/Telegram 替身，不真实等 90 分钟。
必要的严格类型/lint、受影响回归及原发布管线按批次执行，不为仅文档改动跑运行测试。

语义验收另用真实模型和非私有合成对话，分别覆盖冷场主动提问、普通回合追问、待说想法、旧事接续、
有限搜索、无人接后放下、明确结束、适合沉默；不能用固定替身输出证明主动性。
至少记录样例输入、实际主模型/参数、是否形成相关主动内容、是否具体提问、是否接续回答、
重复/不合适追问、调用数/Token/延迟。联网话题核实来源，不强求固定句子。
离线评估不向真实群发送探测消息；安装镜像中验证实际加载的代码、配置契约与临时数据链路。
上线后本人真实聊天作为持续反馈，不以额外聊天积累延迟可运行批次发布。

## 9. 运行可见性与最终交付

在既有状态/记录接口提供：下次/上次检查、最近成员来信、空闲时长、基础/修正后概率及抽样结果、
跳过原因、机会 ID、主回合状态、发送结果、关联事项/尝试次数和放下原因。
区分“检查未命中”“机会未投递”“主模型沉默”“发送失败/未知”“确认已发送”，避免再次将 completed 误称主动发言。
不新建 M5 面板，不记录凭据、完整私聊副本或详细思维链。

最终发布记录应说明：四项目标实际行为、与 qq-bridge 的保留差异、字段迁移、本人实例启用参数、
schema、确定性/实际模型验收、成本、提交/镜像、备份和健康结果。
V4 完成后再重新核对 V2-D/E/F，V2-C 已并入部分不重复开发，其余统计是否需要届时判断；M5 继续暂缓。
完整黑话学习、成员画像扩展、媒体表达、查询/分条大改均不作为 V4 前置。
