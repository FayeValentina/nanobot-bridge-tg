2026-10-29。本批覆盖 G01–G04，继续使用现有 SocialStore、SocialScheduler 和 Agent 会话入口。
实现、定向验收、完整管线与实际实例发布已完成，三个新机制已在本人实际配置启用。

## 对话行为

- 自动合并从最后一条获准的新成员消息重算静默；“但是/然后”等未完成句和短句延长等待，完整问题、终止标点采用短路径，明确要求立即回答可缩短到 0.5 秒。
  每次候选有固定总等待上限，后续消息、释放锁和重启均不能重置上限。达到上限但尚未安静时，快照返回 `dialogue.quiet=false`。
- `social_wait(seconds, sleeping, on_timeout)` 原调用保持原义。新增 `purpose="reply"` 表示首答前等下文；已安静足够立即返回、不结束当前回合，否则持久化续接并释放锁。
  自动合并已经消耗的总期限继续约束本次首答等待，不再叠加一个完整窗口。续接绑定原消息，即使它已展示或标读也不会丢弃。
- `purpose="messages"` 表示等新内容，然后等静默。`seconds` 是总期限，`quiet_seconds` 是静默窗口；无新消息不会因静默窗口结束而唤醒。
  默认无消息超时本地结束；显式 `on_timeout=true` 仍受一次性水位约束。关键词/指定成员的筛选、一次性消费与 TTL 保留。
- 公开发送得到真实平台确认后建立短期关注。相关性采用本地可解释规则：本回合实际展示过的成员继续发言，或新消息引用已确认的机器人消息。
  不用分类模型；机器人被唤醒后仍可沉默。发送途中已到达但未展示的相关消息也会进入候选。
  分条组只在最后一个子动作确认后建立一次关注；普通 message 的确认回执也支持关联。queued/failed/unknown 不建立成功发言关注。
- 答后检查点只进行本地消费；没有新内容不再调用模型、不催话、不续设同一个检查。关注窗口仍可继续接住稍后回答。
  显式选择性等待优先，普通关注不会绕过它。没有启用“无消息也调用模型复查”的兼容模式。
- 启用睡前观察时，模型请求潜水会在必要时原子保存“观察后潜水”，结束当前回合。
  无人继续发言时本地转为潜水；有新内容时先形成合并后的快照，让模型重新选择是否参与。
  模型输入中实际出现的快照才产生观察证据，收到消息本身不算；成功公开发言重置证据，重放同一旧快照不会恢复旧凭证。
  已连续安静满窗口、关闭观察，或当前实际展示的最新成员消息以明确告别用语结尾，可以直接潜水。不会自动发送告别。
  `social_mark_read` 保持独立的连续水位确认操作。

## 配置契约

配置位于既有 `channels.telegram.social` JSON 编辑入口，manifest 默认值由同一 Pydantic schema 生成。
新增能力的代码默认均关闭，旧配置升级保持兼容。本人实际实例在本批发布时启用三项：

```json
{
  "dynamicWait": {
    "enabled": true,
    "quietSeconds": 1.5,
    "unfinishedSeconds": 4,
    "maxSeconds": 12
  },
  "replyAttention": {
    "enabled": true,
    "checkSeconds": 30,
    "windowSeconds": 120,
    "questionWindowSeconds": 300
  },
  "sleepObservation": {
    "enabled": true,
    "windowSeconds": 300
  }
}
```

以上是 social 下的增量字段，不是完整 config.json。群范围、allTopics、角色、昵称、模型、普通工具权限、
主动机会 1800 秒、quietHours 关闭、每小时 120 次唤醒和 60 次 social 发送尝试保持原配置。
`social_get_state` 返回新配置及当前等待/关注期限；各实际话题分别保存状态与发送路由。

## 持久化、竞争与恢复

social schema **6 → 7**，事务新增：

- `dialogue_state`：最后有效来信时间、真实模型观察凭证。
- `dialogue_waits`：用途、起点、静默/总期限、已展示水位、原消息、观察后潜水及临时条件过期。
- `dialogue_attention`：确认发送动作、参与者、消息水位、关注截止和已消费检查点。
- `dialogue_jobs`：候选关联的等待来源、静默/总期限与快照说明。
- 普通 `message_deliveries.version`：发送途中更改配置后，旧回执不在新版本建立关注。

观察入库、消息去重与动态候选更新共用事务；等待期限消费与续接候选写入共用事务。
事件、显式等待续接和主动机会复用同一待执行候选；点名优先，仍由既有请求额度、有效期和单会话执行约束准入。
候选入队与模型准入均检查来源尚在、配置和状态有效；已读不是首答续接失效的依据。
暂停、撤权和绑定/配置版本变化清除旧等待、关注与观察凭证，保留历史、水位、记忆和角色。
重启保留仍有效的静默期限；错过时效或时钟跳变不会集中补发旧任务。未知发送沿用不自动重发规则。

旧代码不支持 schema 7，也不接受这些新配置字段。回滚使用原管线恢复对应版本和整实例备份。
