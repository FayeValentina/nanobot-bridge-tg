## 会话消息增量写盘

- 普通保存仅向 JSONL 追加新消息，将最新元数据、provider 私有状态、提交字节位置和消息数原子写入同名 `.state.json`。改标题等元数据更新也不再重写整份消息日志。
- 状态文件是提交点：追加前先建立旧提交的边界，崩溃未提交的尾部不进入读取结果。完整替换使用新的显式存储版本，旧状态文件不会覆盖新日志。
- 旧 JSONL 继续可读；每个会话建立基线时、修改历史前缀、压缩或缓存被淘汰后采用原子全量替换。缓存最多保留 16 个会话，通过实际消息值比较判断追加资格，不引入哈希。
- 读取、修复、列表、WebUI 侧边栏及 provider 状态使用同一提交视图；状态文件变化也使侧边栏缓存刷新。删除同步删除状态文件；旧布局迁移和显式降级导出会物化成完整 JSONL。
- 工具回合 checkpoint 绑定显式存储/保存版本，保留旧 checkpoint 的兼容读取。仅建立旧提交边界或更新标题不应误删尚有效的中断恢复点。
- 消息前缀比较仍为 O(历史长度)，provider 私有状态仍整体保存，因此本批不声称所有持久化开销已变成 O(新增消息)。

## 回合组织

- 从 loop.py 提取 TurnOptions、TurnContext 和 TurnKind，内层处理方法接收一个选项对象；公共 process_direct 参数保持兼容，旧私有关键字调用保留边界适配。
- 提取 PendingMessageBuffer，单独管理有界排空、等待子任务结果及总超时；消息内容/媒体和运行时上下文装配语义保持。

## 数据职责

JSONL 加同名 state 文件共同构成会话上下文的已提交真源；checkpoint 是可被新保存取代的运行中恢复层。社交 SQLite 是观察、水位、调度与投递回执的真源，MEMORY.md 是整理后的长期记忆，WebUI transcript 是展示历史。它们不互相替代；清理某一层不能宣称抹去其他层的数据。

回滚继续使用发布前完整数据备份。直接交给旧版本的 JSONL 应走显式导出，不能只复制忽略状态文件的原始日志。

剩余：转录回放、网关生命周期等大模块仍可继续按职责拆分。具体发布版本与结果以实际实例 state.json 为准。
