# V3 广泛放行普通群聊

2026-10-31，用户要求大幅放宽 V3：群友不应每天先叫名字，主模型应能看到普通群聊，
自己决定接话或沉默。此约定取代旧样例中仅凭“问别人”“只是引用”“缺少明确切口”就 observe 的预期。

## 原因

11:29:54（UTC+8）的消息 6880 连续重复“token 来！”，11:29:55 已被正常接收，
eligible=true。V3 在 11:29:59 正常返回 observe，理由为“不是对肥鱼的明确呼叫，
也没有自然的聊天切口”，没有主模型唤醒或发送尝试。
11:43:11 加 @的重发则被判 wake，11:43:22 确认发送消息 6882。
这不是接收、超时、限额或 Telegram 发送故障，而是中间模型的参与标准过窄。

## 改动

- V3 提示词按明确优先级重写：普通观察/一般聊天等待中新鲜群聊默认 wake；
  没有任务、问号、名字、邀请、前置共同话题或高信息量，也能交主模型。
- 普通闲聊、玩梗、重复口号、笑声、emoji、情绪、抱怨、引用、代码讨论、
  未说完的口语、图片/贴纸及其他成员之间的公开交流，均使用同一宽松标准。
- “这条只问另一位”标明问题收件人，不自动禁止主模型旁听公开对话；
  是否适合插话由主模型决定。明确私人交流、明确要求其他人不要插话，才保留 observe 边界。
- 明确选择性等待仍有效。直接呼叫、偏好纠正、停止/取消要求继续唤醒以应用行为，
  不代表一定要公开确认。一般潜水、背景观察和 standing on_question 不构成点名/问题门槛。
- 正确认账号仍然必要，但相似名字、引用和他人收件人识别只用于理解语境。
  不靠误认“这是叫我”来证明公开群聊能放行。
- 角色摘要的“没兴趣就安静”等偏好交主模型执行，不能再次变成 V3 的兴趣过滤器。
- 提示词版本升至 social-judge-v8；现有显式修订机制使旧 pending 判断失效。
  不新增本地关键词强制唤醒、概率筛选、互聊上限、身份或内容哈希。

自身消息、编辑、消息 ID 去重、旧/未来消息、暂停和观察授权的宿主保护保持原值。
模型、OAuth、工具权限、V4 主动策略、发送额度与数据库 schema 不变。
更宽松的 V3 会增加主模型看到消息的机会和调用量；wake 并不强迫主模型公开回复。

## 验证方式

导出实际失败批次的完整 30 条模型输入（含当时旧人设、时间和账号信息），
仅在临时库/直接模型输入中回放，不推进实际群水位、不补发历史消息。
另外用实际 V3 模型执行新增宽松场景和按新原则修订的既有场景。
评估器增补 group_meme/public_chatter/emotion_share，验证 V3→主模型→替身发送。
没有真实群发送探针，也不把小样本结果当作长期准确率。

首版草案仍曾把对其他成员的纠正当作不相关，也出现“理由说封闭交流但返回 wake”的不一致。
因此精简为有顺序的规则，并明确“别人是问题收件人”与“禁止旁听/参与”不同；
最终版本重新执行完整场景，早期报告保留在私有验证目录。
