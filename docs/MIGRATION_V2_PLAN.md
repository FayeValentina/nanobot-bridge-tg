## 3. 不变约定与实现边界

- 继续使用一个 Telegram 更新接收者、一个 SocialStore 所有者、一个 SocialScheduler 和既有 Agent 会话执行入口。
  新期限、候选、关注状态和任务都由现有 social SQLite 管理；不增加第二套 LocalTrigger 重试队列或常驻学习服务。
- 业务留在 Telegram social/工具边缘；仅在现有 hook 无法表达通用生命周期时，才增加小范围核心接缝。
  不把仿真状态机写进 runner，不为遵循草图建立空目录或抽象框架。
- 群友与普通助手保持相同工具权限，文件、命令、MCP、技能、后台/跨会话投递、共享记忆和 Dream 保持可用。
  social 工具自身的作用域、调度、预算与真实回执约束继续有效。
- V2 当前的只观察、统计、抽样、等待、检查候选和满足睡前观察条件均不调用模型。
  V3 启用后，新消息批次会调用中间模型；旁观不再保证零模型成本，无新消息/有效事件仍不空转。
  唤醒仍可沉默；不为“像人”强行生成催话、退场或随机句子。
- 内部最终文本不公开，普通发送不能被误记为 queued 即 sent；unknown 不自动重发。
  已读只能推进本回合实际展示的连续前缀；新功能不能越过缺口或确认新到未展示消息。
- 群/话题保持独立历史、关注条件、水位和发送路由。allTopics 表示每个话题启用，不表示把话题消息混成一个池。
- quietHours 仍只控制主动机会。新增消息类概率/提问触发不会自动变成全局免打扰的一部分；
  若以后需要统一免打扰，应单列契约，不在本轮隐式改变其含义。
- 角色和背景按现有可信来源装配；统计、记忆、反馈和表情笔记均为有界资料，不能升级为系统指令。
- 所有新配置进入 Pydantic schema、manifest 和既有 JSON 编辑契约；运行时动态值不塞入 config.json。

## 4. 先行批次：对话核心机制

### V2-A：等人说完、接住后话、睡前观察（G01–G04）

**已完成并发布**：`93fcb83f`，schema 7，新增 56 项定向验收，三个机制已在实际实例启用。
以下保留批次目标；实际字段、默认值、相关性规则和发布参数见 [实现与发布记录](V2A_IMPLEMENTATION.md)。

**交付目标**：连续拆句不抢答；机器人问完后仍关注回答；潜水前能继续听，但不长期占住执行锁。

1. 将“首答前等待补充”与“答后等回复/睡前观察”作为显式用途，不用一个 seconds 模糊代替。
   保留现有 `social_wait(seconds, sleeping, on_timeout)` 调用兼容性；拟扩展 purpose/quiet/总期限参数，
   字段名在本批实现时统一冻结，不能静默重解释旧调用。
2. 短窗口合并支持从最后一条来信计算静默，连续新消息可延后，但不得超过首次候选的总等待上限。
   明确首次入站自动合并与模型显式请求等待的边界，不能叠加两个完整等待窗口。
3. 用本地规则识别“但是/然后/我跟你讲”等未完成句和短时多条输入，只作为软信号。
   终止标点、明确完整问题和“马上回答”等直接请求采用较短路径；错误判断也必须在上限内结束。
4. 等待决定、最后来信时间、静默截止、总截止、起始/已展示 seq、用途与版本持久化。
   `reply`：已安静足够立即返回；否则登记一次续接并结束当前回合。
   `messages`：无新消息不把 quietMs 当总超时；有新消息后重新计静默，达到总上限时显式标记 quiet=false。
   后台到期只产生候选，模型调用前仍校验时效、来源、预算、当前版本与并发状态。
   “静默已足够，需要继续首答”绑定原始待回答消息/等待意图，不能因该消息已展示或标读就丢弃；
   消息事件、等待续接、睡前观察完成和答后检查分别定义有效性，不能统一用“还有未读”决定是否执行。
   期限消费与续接候选入库必须处于同一事务，重启不得留下已消费但无法续接的半状态。
5. 睡前观察拟建议启用、窗口 300 秒，必须可配置。模型请求潜水而观察未满足时，
   原子保存“观察后潜水”的意图，并结束回合；不得只报错让模型反复调用等待。
   无人继续发言时可本地转入潜水，不再叫模型确认；有新消息时按合并规则展示给模型再决定是否参与。
   仅“已经收到”不算“模型已观察”；成功公开发言后重置本次睡前观察凭证。
   明确告别、已连续安静满窗口及关闭观察配置的情形可直接收尾。
   `social_mark_read` 保持纯水位操作，不因睡前闸门而拒绝确认真正看过的消息。
6. 确认发送后建立短期关注窗口，默认检查点拟为 30 秒；机器人提问可延长。
   关注期内普通相关新消息可唤醒，显式关键词/发言者等待仍保持筛选，不被通用关注覆盖。
   一个分条组以最后确认子动作建立一次关注；当前群普通 message 的确认回执也可关联。
   unknown/failed/仅 queued 不建立“已经说过”的关注状态。
7. 回复检查绑定发送动作和消息水位；已有更新的事件候选、主动回合或显式等待时合并/让位。
   无新内容默认本地结束，不重新调用模型；检查产生的沉默不能再安排同一检查。
   若提供原版“无新消息也复查一次”兼容选项，须显式开启、计入额度并限制单次，不默认启用。

**必须验收**：

- “我明天去台湾 / 但是 / 护照找不到了”只形成一次包含完整三条的首答；持续刷屏仍在总上限内进入一次回合。
- “你什么时候出发？”确认发送后，用户半分钟后回答“下午三点”，无需再喊昵称即可接续；无人回复时不空转。
- waiting/sleeping 不持有会话锁；等待期间 @、暂停、配置变化、重启、时钟跳变和模型错误均能正确收尾。
- quiet=false 不被说成用户已讲完；观察未展示消息不能变成已读；睡前观察不中断明确点名、不自动发送告别。
- 同一新消息、发送组和期限最多认领一个有效回合；旧 timer 不重复触发，未知发送不诱发重发。

### V2-B：补全触发器与潜水中断条件（G05–G08）

**已完成并发布**：`29579798`，schema 8，新增 102 项定向验收，本机已启用提问、5% 概率和指定条件潜水中断。
以下保留批次目标；实际字段、兼容默认值、规则和参数见 [实现与发布记录](V2B_IMPLEMENTATION.md)。

**交付目标**：不仅会被叫醒，也能按临时关注条件等到特定内容；保留可靠的基本点名入口。

1. 增加独立 question 候选，结合当前消息的称呼/机器人身份、引用对象和提问/挑战特征。
   群友互相提问、引用旧消息里提到机器人、问号或人名相似都不能单独触发。
   检测使用本地规则，不用分类模型；不确定时交给其他已有触发，不凭空扩大唤醒范围。
2. 支持普通消息概率抽样，概率范围 0–1；只对通过观察授权的新普通成员消息抽样一次。
   排除重复更新、自身/机器人消息、过期事件、暂停及不允许被该条件中断的潜水。
   抽样结果与关联 seq 落盘，重启和限频延期不能重新掷骰子；高优先级点名覆盖随机原因。
3. 将模式与触发条件解耦：潜水可选允许关键词、发言者、提问或概率中断。
   当前“sleeping 忽略普通触发”为旧配置兼容值；启用新策略后允许配置的条件穿透。
   `waiting` 中选择性条件继续过滤普通消息；one_shot 在准入时消费，TTL 继续限制候选寿命。
4. 支持有限时长、绝对到期和无到期等待。绝对时间必须有明确时区或偏移，
   不接受模糊本地日期；有限/无限、TTL、暂停与角色/配置版本之间的关系必须校验。
   无限等待不等于无限临时条件；超过临时条件上限后回落到管理员基础触发。
5. 每作用域可选合并窗口仍受管理员总上限约束。基本 @/回复可达性保留，
   模型不能改观察权限、额度或通过设置全部条件为 false 令启用中的群永久不可达。

**必须验收**：提问指向准确；0/1 概率边界、随机源可控；重启不重复抽样；关键词/指定成员可按新配置打断潜水；
直接点名与随机/到期候选只执行一轮；临时条件过期或消费后不继续拦截后续聊天；无限等待可被点名和暂停解除。

### V2-C：参与分寸与主动节奏（G09–G10）

**2026-10-30 已调整优先级：本批不再先行实施。** 必要统计和 G10 主动调度并入 [V4](MIGRATION_V4_PLAN.md)，以还原主动交流为交付目标。以下保留旧方案，尤其来源前置和旧配置固定周期的要求不约束 V4 独立冷场机会；V4 后重评剩余范围，不重复开发已并入部分。V3 新消息入口不恢复消息概率触发树。

**交付目标**：根据热闹程度、自己刚说过多少和是否有值得接的话调整参与，不靠固定概率一直插嘴。

1. 计算近一小时自己/群友发言量、近两分钟自己发言量、近五分钟消息/活跃人数、距最后确认发送的时间和直接未读。
   发送以真实平台确认计数，unknown 不伪装 sent；分条可同时提供消息数和发言组数以免误判。
   保留窗口不足时标记统计不完整，不能把淘汰后的记录当成零发言。
2. 生成有长度上限的事实与参与建议：连续说过可少说、多人对聊可挑重点、直接找自己优先回应等。
   只做软提示，不硬性禁止模型正常答复，不让统计成为人设或持久记忆。
3. 在 M4 主动机会前增加可选随机间隔、空闲阈值、基础概率、近期回复/发言偏多降权和 pending 加权。
   next_check 与本次抽样持久化；老 intervalSeconds 仍为兼容固定周期入口，不能因升级即改变现有节奏。
4. 概率通过也须有有效来源；requireContext=true 的零上下文零调用、每记忆修订/消息来源去重继续保持。
   可另外显式配置 requireContext=false 的周期机会，不把“随机”当成绕过来源约束的入口。
5. 原版夜间概率降低与现有 quietHours 分开：quiet 开启时主动机会直接跳过；
   quiet 关闭时可选夜间降权，但不能变成隐式禁言；显式点名不参与主动降权。

**必须验收**：群聊洪峰不重复调用模型；刚发多条时提示准确；热闹不强制插嘴；沉默不反复消费同一来源；
原配置继续固定周期；随机期限跨重启稳定；quiet、DST、暂停和点名竞争仍通过既有回归。

### V2-D：可靠收尾、自然分条、查询与反馈（G11–G14）

**在 V3 后适配**：修复针对中间判断/主回合状态，不恢复旧关键词/问句/概率语义入口。下文原方案据此调整。

**交付目标**：补齐对话执行的收尾和查询能力，保持可诊断、不重复发言。

1. 定义“有行动”：确认发送、显式等待、设置有效关注条件、合法沉默/已读收尾等分别记录。
   合法沉默不累积为卡死；模型/API错误、工具失败、发送 unknown 与未解决 unsent 也不能混为“没说话”。
2. 复用现有一次漏发确认，统一每回合修复上限；不能分别叠加“漏发提醒”和“忘记设置唤醒提醒”形成调用链。
   连续协议失效达到阈值时本地清理无效临时条件、恢复管理员基础触发，并记录原因。
   不清群历史、水位、记忆、角色和暂停决定，不重放可能已送达的旧内容，不因修复自动补一轮闲聊。
3. 分条最大数量配置化，目标覆盖原版上限八条；三条仍可作为默认推荐。
   支持固定/随机/按字数间隔及有限长间隔概率；随机间隔每组只计算一次、存为 due，重启不重新生成。
   冷却是最小约束，延迟不占 Agent 锁；总预算预检、逐条复验、动作过期、暂停、部分失败/unknown 取消后续继续有效。
4. 优先扩展现有读取工具的 action/filter，提供自己最近已确认发言、按本地 seq/message_id 查询详情、活跃成员。
   有界分页、截断和历史缺口显式返回，不从库外获取不可见群历史。
   “已观察成员”与 Telegram 实际能查询的成员/管理员接口分开命名，不承诺 Bot 能列出全部群成员。
5. 反馈先写本地结构化日志/数据库并提供查询，区分 info/warning/error，限制正文长度、频率与保留量。
   若提供 owner 通知，必须配置真实目标且默认关闭；记录成功不声称通知已送达。
   这里是产品可配置机制，不授权开发验收向真实群或他人发送测试通知。

**必须验收**：连续合法沉默不重置配置；重复提醒受统一上限约束；错误可定位到 turn/action；
八条分组中的失败/unknown 不重复前缀、不越话题；排队与发送状态真实；查询不越作用域；反馈不泄漏凭证。

**先行完成定义**：G01–G14 全部有实现、受影响验收与实际发布记录，保留差异已明确。
V2-A–D 的完成不以 V2-E/F 或 M5 为前置，也不宣称已覆盖所有原工具。

## 5. 后续批次：学习与表达

### V2-E：黑话学习与更完整的群知识（G15–G16）

**2026-10-30 范围调整**：待追问问题、待说想法及动机提前并入 [V4](MIGRATION_V4_PLAN.md)，不等待本批。以下为其余能力和原范围参考，V4 后重评，避免重复实现。

- 在同一 social 存储中保存有界学习任务、候选来源、状态、失败与下次期限；复用普通后台执行能力，不增加第二个 Telegram 接收者。
- 按消息数量/时间窗口批量选取素材，去除命令、控制文本、重复引用；模型提取只在显式启用且达到批次条件后运行。
  单独声明学习额度、窗口上限、每批候选数、重试次数及无素材零调用规则，不能冒充“旁观永远零模型成本”。
- 提取与联网考究分步，联网资料与群内原始证据分开保存；搜索结果不能自动证明群里同一个词的含义。
  确认条件、候选状态、纠错/删除、证据抑制和 TTL 继续沿用 M4，独立 learner 不直接写共享 SOUL 或改人设。
- 学习任务的证据必须实际进入学习模型输入；不能借 learner 曝光推进聊天模型的 seen/read 水位。
  老消息被清理、删除或索引被 clear 后，排队任务重新校验，不能复活已删除知识。
- 拓展 topic 的参与者/待追问、pending 的动机、成员印象的有证据特征。
  成员使用稳定 ID；互动次数/最近互动优先从消息及已确认回复计算，不因重复记录一条印象就自增。
- 默认仍按来源群/话题检索；不建立全群共享画像或全局黑话同步作为隐含副作用。

**验收**：受控批次成本；候选不自动变事实；搜索失败不编造；任务重启/取消/删除不重复提交；
模型输入证据可查；学习与聊天水位互不混用；旧的纠错/删除/清空抑制规则仍通过。

### V2-F：动画、表情语义、语音与平台资料（G17–G20）

按 F1–F4 独立交付，避免媒体依赖拖住文字核心发布：

1. **F1 表情语义维护**：扩展现有 sticker 的查看图片、修改 note/tags/usage、搜索与本地库刷新。
   不另建第二份语义库；资料变化不改变平台账号官方备注，误操作可纠正。
2. **F2 动画**：GIF/WebM 按需抽有限帧、标时间或拼图，保持原件与模型副本分离；
   TGS 渲染单独明确依赖和资源限制，不假设 ffmpeg 可直接处理所有格式。
   动态贴纸/动画发送逐格式核验 Telegram 当前能力、file_id 和格式约束，覆盖超限、超时、缺转换器与降级。
   依赖纳入现有 Docker 构建，文字能力不被媒体失败阻断。
3. **F3 语音库**：查询本地可用片段与时长/体积，按平台语音形式发送并返回真实 message_id。
   可选库路径按普通文件边界解析；普通 message 仍能发送附件，不增加群友专用权限限制。
   Bot API 发送成功只证明平台接受，不能声称已通过 QQ get_msg 式回读或听者已收听。
4. **F4 自身资料与转发**：提供可取得的 Bot 身份/头像和已收到转发的文字、作者来源可见性及媒体。
   不补造 Telegram 隐藏的作者信息，不承诺读取 QQ 式任意合并转发容器或服务器历史。

**验收**：媒体预算、路径与网络边界、并发、缓存清理、准确降级、发送回执、unknown/429、暂停/恢复、
话题路由和静态贴纸回归；缺依赖时仍可正常文字交流。

G21 始终保留平台差异清单；如以后引入 Telegram reaction/其他动作，需要独立定义触发和公开动作语义。
G22 保留到原 M5，恢复 M5 前先核对后端契约，不照旧草图重复实现已完成的日志、清理或升级接口。

## 6. 配置与状态设计

以下是字段分组草案，**不是完整可直接粘贴的配置**；V2-A/B 已冻结字段见各自实现记录，其余在对应批次冻结。

| 分组 | 拟配置内容 | 兼容要求 |
| --- | --- | --- |
| 对话等待 | 双用途、静默下限、未完成句延长、总等待上限 | 原 seconds/sleeping/on_timeout 继续可用 |
| 睡前观察 | enabled、观察窗口、明确告别例外 | 不阻止 mark_read；等待与静默可本地完成 |
| 答后关注 | enabled、关注窗口、检查延迟、最多检查次数 | 不覆盖显式选择性条件，不为无新内容默认调用模型 |
| 唤醒策略 | question、probability、睡眠中断条件、每 scope 合并窗口 | 原 wakeKeywords/wakeSenders/wakeOnMessages 可映射，原 sleeping 默认行为保留 |
| 主动节奏 | 固定或随机间隔、idle、基础概率及降权参数 | 原 intervalSeconds、requireContext、quietHours 保留 |
| 参与与分条 | 统计窗口/提示长度、最大条数、间隔策略 | 默认长度与总预算仍有边界，普通 message 权限不变 |
| 学习与表达 | 批量阈值/独立学习额度、表情/语音/动画限制 | 学习成本明确披露，新增后台提取默认关闭 |

代码升级采用兼容默认；发布当前实例的功能预设另行记录，区别“能力已支持”与“该群已启用”。
V2-A 的动态等待、答后关注和睡前观察为先行启用目标；具体数值以受控时间测试和当前本机参数落定。
V2-B 的概率唤醒建议从低概率起步；原版 0.05 为参考，不硬写为所有群默认值。
变更参数属于该功能发布的一部分，沿用本人本机授权和备份流程，不建立额外审批门槛。

状态至少要能表达关注用途、起始/最新消息水位、静默/总截止、观察凭证、关联发送动作、
候选原因/来源、抽样结果、检查是否已消费、修复次数与决策理由；按批次按需落表，不提前建空框架。
只持久化恢复必需的值；参与度尽量从有界消息/发送记录计算。
每次状态转移写清前置条件、事务内更新、过期处理、取消来源和重启行为。

## 7. 共同验收矩阵

| 场景 | 预期 |
| --- | --- |
| 拆句与连续补充 | 等待静默、有总上限；不会按每条都叫模型或重复回答 |
| 问完等答 | 普通后续回复可接续；没有新内容不自言自语，不无限自唤醒 |
| 多人互聊 | 识别引用对象；问号不抢答，参与提示不强迫发言 |
| 睡前观察 | 等待释放锁；无新内容本地完成；真正看到的消息才产生观察/已读证据 |
| 点名竞争 | @/回复优先，概率/主动/等待检查合并；一个 scope 同时只有一个有效执行 |
| 选择性条件 | 关键词/指定成员筛选有效；按配置可打断潜水；TTL、one_shot、取消词和主动清空有效 |
| 暂停/撤权/变更 | 旧候选、观察意图、分条与学习任务失效；不误删普通历史 |
| 故障与恢复 | 限流不丢仍有效候选；超时 unknown 不重发；停机过期不集中补发 |
| 跨话题 | General、既有/新话题均生效，各自水位、条件与发送不串线 |
| 上下文与压缩 | 当前状态/统计是有界新鲜资料，压缩后不丢人格、不恢复过期条件、不重复加入旧提示 |
| 权限与普通助手 | 文件/命令/MCP/技能/共享记忆/后台及跨会话 message 的原能力回归通过 |
| 数据升级与回滚 | schema 6 起的逐版升级保留数据；坏库拒绝当空库覆盖；旧代码与对应备份一起恢复 |

测试采用可控时钟、可注入随机源、真实临时 SQLite 与模型/Telegram 替身，不真实等待五分钟，不发真实群测试消息。
每批跑必要的定向回归、类型/lint 和既有管线；检查通过后再进入构建发布，不为文档改动跑整套运行测试。
自然程度用本人本机后续实际聊天反馈评估，不能把替身测试通过表述为“已证明像真人”。
