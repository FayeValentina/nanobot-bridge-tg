# 普通助手与群友模式共用工具权限

2026-10-28 用户明确要求：群友模式和普通模式使用同一套工具权限，差别只在消息传递、
观察、唤醒和潜水机制。本约定取代 M0–M3 早期的群友专用白名单、角色不可修改、
个人资料/技能/记忆禁用及后台投递限制。

## 当前行为

- 普通会话和群友会话使用同一个工具注册表、相同的全局工具开关。文件、命令、MCP、
  技能、会话工具、定时任务、子任务和持续目标不再因 social 模式被隐藏或禁用。
- 不再为群友模式单独关闭个人资料、私人技能、长期记忆、运行时资料和正常记忆归档。
  原有全局配置和普通权限机制继续适用于两种会话。
- 角色仍从当前绑定文件加载。`social_get_state` 返回当前 role_id、运行环境内 role_file，
  以及 `tool_permissions: shared_with_normal_chat`，不再返回固定的不可编辑标记。
  模型可用普通文件/命令工具修改角色；文件、工作区和容器权限按普通规则执行。
- 角色内容修改在下一回合加载，当前回合可继续确认修改。角色内容版本用于更新会话上下文；
  调度版本取配置与消息协议，修改角色文字不再取消当前唤醒或已排队的发送。
- 普通 `message` 工具可以向当前群友话题发送文本/附件，也保留普通跨会话发送能力。
  后台使用的 `chat_id:topic:thread_id` 路由由 Telegram 通道解析，保留原话题。
- 群内斜杠命令交回普通命令处理器，使用普通的发言者授权。定时/后台回合不需要伪造
  social WakeJob；只有 social 调度器投递的消息会认领该任务。
- 老会话中的 `_isolated_context` 标记在加载时移除。关闭 social 后恢复普通策略，
  不保留隐藏的旧工具或上下文限制；原始会话文件继续保留。

## 群友消息机制

普通群消息仍先观察，符合条件才唤醒模型。合并窗口、忙时合并、等待、潜水、一次性超时、
静默收尾和重启恢复保持。最终文本和内部工具进度不会自动成为群消息，公开内容显式发送。
持续目标仍可续轮；潜水会释放当前执行回合。

`social_send` / `social_sticker` 是带冷却、预算和平台回执的当前话题发送接口，
`social_get_media` 读取已观察的媒体，`social_mark_read` 确认实际展示的水位；
这些数据/调度接口的参数语义继续有效。通用工具保持自己的普通能力与发送语义，
不会被一个 social-only 的发送总门禁静默丢弃。

## 验证与发布

验收位于 `nanobot/channels/telegram/tests/test_shared_tools.py`，包括两种会话的工具列表
和全局开关一致、真实文件/命令工具修改角色并确认、下一回合角色更新、通用 message 文本/
附件/跨会话投递、后台话题路由、动态注册工具和旧隔离标记迁移。
原有群友测试已按新要求改为共用权限，继续验证观察、角色绑定、潜水、媒体与发送回执。
发布使用现有本机管线，配置和角色不额外改写；发布结果以实例 state.json 和本机管线说明为准。
