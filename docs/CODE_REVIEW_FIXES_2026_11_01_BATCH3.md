# 2026-11-01 审查修复：第三批

本批按用户指定的标准构建并启动实际实例；不运行测试套件、故障注入或额外业务验证。

## 旧版本部署门禁

- wheel 内新增显式会话格式声明，release.json 记录可读格式列表，并与实际 wheel 声明比较。对已有本地旧产物，传统 JSONL 按格式 0 处理，已发布的 incremental_log 布局按可读 0/1 兼容。
- deploy 在停止健康实例前读取当前会话所需的提交格式，目标不支持时直接拒绝，不修改会话数据。
- 所有 Compose up 统一再次检查，覆盖正常部署、失败恢复和回滚，防止预检查与停机之间生成新的提交状态。
- rollback 停当前实例之前，先检查目标旧版与它自己的匹配备份是否兼容；恢复备份后启动还会再检查。保留原有完整数据备份和失败回滚流程。
- 本批不自动转换当前数据来强行降级；保留最新数据的降级必须先用当前运行时物化会话。手工绕过本机脚本直接启动镜像不在门禁覆盖范围内。

## checkpoint 版本读取缓存

- checkpoint 的写入和恢复共用按文件身份、长度及 mtime_ns 失效的版本缓存；日志与 state 都未变化时只读 stat，不再完整解析 state JSON。
- 本进程完成全量保存、追加提交、元数据更新后直接刷新缓存。外部替换或变更文件会触发重新解析；解析前后文件发生变化则不缓存该结果。
- 版本缓存最多 128 项，不保存消息或 provider 私有载荷。会话内容读取仍按原有完整校验逻辑执行。

## baseline 预算

- 保留最多 16 个会话，并增加合计 32 MiB 的 Python 对象估算预算。计入消息快照、提交头与 provider 状态；这是缓存持有量的估算预算，不是进程 RSS 或临时分配的操作系统硬限制。
- 复制前估算大小，单个过大的 baseline 不进行 deepcopy；其他条目按 LRU 淘汰。超预算不影响已提交数据，后续保存继续采用现有全量替换路径。
- 追加时只估算新增消息及新提交状态，沿用旧消息的累计估算，不额外遍历全部旧消息做内存计量。共享对象的重复计量采用保守口径。
- 消息前缀比较仍为 O(历史)，provider 状态仍整体保存，本批不声称消除了全部线性开销。

提交、构建和实际启动结果以本机 release/state.json 及本次交付说明为准。异常恢复与降级路径未经过故障注入验收。
