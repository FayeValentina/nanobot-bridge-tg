# 空闲时自主活动

2026-11-01。用户要求：空闲时自己找活干，过程中在群里吐槽或分享有趣的发现。
用户随后明确这不是工作系统，不需要核验结果、交付物或强制完成。本批按休闲兴趣实现；
自主活动与主动追问/通知分开，自然度与线上实际效果仍需实际使用观察。

## 行为

启用 `proactive.activityEnabled` 后，既有定时队列产生 `kind=activity`，进入原主模型和普通工具执行链。
默认每600秒检查，主回合有效期300秒、最多8次模型迭代；软件仍默认不启用，实际实例在发布后开启。
此时不再用原发言概率、近期发言倍率或发言预算决定是否有活动机会。
发言继续走原发送预算、间隔、scope与回执；安静浏览、玩耍、探索也可以。
请求预算、成员最近活跃、在途群聊判断、正在执行的回合、暂停、停止主动联系、明确等待和quietHours仍生效。
整群allTopics绑定只在成员最近活跃的话题调度，避免每个沉寂话题重复唤醒。

`social_activity` 是私人兴趣笔记，实时提供当前及最近五项活动：

- start：只需一个兴趣标题。目标、动机、下一步均可不填；新兴趣会把旧兴趣暂时搁下。
- progress：留一句看到什么、玩到哪儿、想到什么的笔记；下一步、产物、引用均可不填。
- pause / resume：随时搁下或重新捡起。complete / block / abandon 可结束或放下兴趣，不要求核验或交付。
- list：查看当前状态。已有条目的修改需要稳定ID和expected_revision。

SQLite schema17增加activities/activity_steps，升级在事务内完成，不改旧表或主/V3游标。
每轮实时注入活动记录，历史压缩与重启后仍可接着玩。已claim的机会重启不回放；后续独立周期读取最新笔记。
不因几轮没有进展自动惩罚或阻塞活动。活动记录是模型的私人笔记，不是对引用产物真实性的自动证明。

提示鼓励实际接触感兴趣的事物，允许浏览、玩耍、半途换兴趣、无产物和沉默，不要求有用的工作成果。
每次活动适度短一些；请求预算、机会有效期和activityMaxIterations为运行时资源上限，
达到上限可以直接结束，不要求产物、笔记或发言。没有另建无限续跑器或绕过 `/goal` 的用户主动授权。
研究、试验、浏览、文件创建和贴纸整理等使用原工具权限，不新增social专用allowlist。

有趣发现、踩坑或小成果可在进行中随口分享；不要求等完成，也不要求每轮发通知。
不虚构错误、忙碌或线下经历。只有发言声称“试过/做成/确定”时，才需有对应事实依据；
这不是开展兴趣、聊天或完成活动的核验门槛。旧事项两次主动联系限制继续适用，私人笔记不算追问。

## 验证与发布

回归覆盖零发言概率/发言预算耗尽仍工作、请求预算/停止/新消息优先、allTopics选择、跨scope隔离、修订冲突、
真实runner写文件/记笔记/中途分享、重启续做与不回放、无目标/无产物/无核验也能切换和结束兴趣，以及16→17迁移失败回滚。
实际模型探针只用临时工作区和替身发送，不启动Telegram receiver，不在真实群发送测试消息。
最终实际模型验证见 `/tmp/nanobot-activity-final-report.json`，与更早的工作导向试验分开保留：

- 无交付要求的休闲场景：自行看目录、读虚构笑话、尝试选贴纸、记兴趣，发出两条短话后等待。
  5次模型调用、15.45秒，没有创建产物文件，也没有要求目标核验。原句：“刚翻到个笑话：鱼去买键盘，
  店员问要机械的吗，鱼说要摸起来像没在上班的。……这鱼懂我。”
- 重启后兴趣接续：从原有小谜题笔记接着玩，修改草稿、留笔记、发题后等待；5次调用、13.44秒。
  这是可以做东西的一个可选例子，不是要求所有兴趣交付成果。
- 两个场景error均为空、正常tool_end；发布为替身回执，未在真实群探测。

这只证明有限情境下会主动接触内容、分享和续接兴趣，不能证明长期自主性、所有发言都自然或所有事实都正确。
选题、发言和留笔记仍由模型决定，没有强制发言频率、产物或核验结果。
