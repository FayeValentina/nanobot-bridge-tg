# 群聊邀请被拦截与冷场频率调整

2026-10-31，用户反馈 V4 后仍不主动发言，普通消息也不回复。

## 实际原因

真实实例收到“没人说话”和后续“？”，V3 均在一次正常模型调用后选择 observe。
理由为没有明确呼叫机器人、没有待回答问题；未产生主回合或发送，非 Telegram 丢消息、模型故障或发送失败。
旧 social-judge-v6 强调明确提及和连续回答，未充分说明普通群友也应考虑开放聊天邀请。
以非私有郊游语境复现，两例均被同样拦截。

定时器在持续检查，但 Asia/Tokyo 夜间基础概率 0.3 再乘 0.3，实际仅 0.09；
近期相关周期均未命中，不存在“已主动发送”的证据。30–90 分钟是检查间隔，并非发言间隔。

## 修改

social-judge-v7 明确：普通观察与一般接话等待期间，开放聊天邀请、寻求陪伴、
有具体交流切入点的近况也可交主 Agent，不要求点名、问号或尚未回答的 Bot 问题。
主 Agent 仍选择具体回复或沉默。点名其他成员、引用文本和显式选择性等待优先按其真实语境判断，
不建立关键词触发词表，不绕过 V3，不改变普通工具权限。

用户选择更积极的本人预设：保留 1800–5400 秒随机检查、900 秒空闲，
基础概率改为 0.6、nightMultiplier 改为 1.0。近期发言/频繁发言等分寸修正和原额度仍生效。
此为本人实例配置，不更改软件对其他用户的默认值。配置变更前备份：
`backups/participation-preset-20261030T164351Z/`。模型、OAuth、群范围、角色和其他配置值保持。
