# V5-C：黑话学习（接管 G15）

2026-10-31。**V5-C 已实现、验证并发布到本人实际本机实例**，运行提交 `7ca2c6fc25ec5926027219acaf471d396444e1d7`。schema **16**；V5-D/E 未实施。本批接管 V2-E 的 **G15**，复用 A/B 的来源、独立游标、批次和后台调度，不另建学习会话、定时器或重复学习流水线。

## 双路径和四态

后台 `JargonLearner` 使用 B 的 worker 生命周期与全局任务槽，从真人顶层文字发现短词、黑话及明确释义。来源类型、消息 ID、revision、sender_id 和原文摘录先逐值校验，合格后才允许联网。SELF、其他 Bot、引用/转发、图片描述和工具/系统内容只帮助理解；普通词不硬造梗，零候选正常成功并只推进黑话游标。

提取模型可以给出一个待核实 `hypothesis`，但程序不会把这个猜测复制到已知含义。群内义只有明确真人解释（同条原文同时含词和释义）或显式操作者纠正才能写入；公开义必须有实际读取正文的支持。候选词支持单字至 32 字，同 scope 的词形/别称直接比较归并到稳定 ID，不用哈希或向量。

| `status` | 语义与行为 |
| --- | --- |
| `candidate` | 未确认含义；可保留标为不确定的假设，不作为既定释义或主动用语 |
| `understand_only` | 可以帮助理解；群内称呼、内部梗和明确本群特殊义默认进入此态，不鼓励主动复用 |
| `usable` | 有正文查证、提取和研究都认为适合公开轻松使用，且没有敏感/群内限定/冲突标记，才自动进入此态；也支持显式管理调整 |
| `disabled` | 有争议、停用、来源失效、过期或删除；普通学习不能自动复活 |

`meaning_status` 另记 uncertain/confirmed/researched/divergent/disputed 等释义依据，不能替代上述四态。自动选择/确认“自然使用”的记录接口只接受当前版本的 usable 黑话；understand_only 不会因为收到发送回执而变成使用范本。

## 工具入口保持静默

新增共享工具 **`social_jargon`**，查询、提交、解释、纠错、调整状态和复核均为后台数据操作，不调用群发送，不触发主模型确认，也不要求先向群友公开追问。

```json
{"action":"get","term":"蓝票"}
{"action":"submit","term":"陌生短词","message_ids":[123],"research":true}
{"action":"explain","entry_id":"稳定ID","expected_revision":1,"term":"蓝票","message_ids":[124],"local_meaning":"临时加场","explanation_quote":"蓝票就是临时加场"}
{"action":"correct","entry_id":"稳定ID","expected_revision":2,"origin":"operator","local_meaning":"操作者明确给出的群内义","reason":"明确纠错依据"}
{"action":"review","entry_id":"稳定ID","expected_revision":3,"reason":"请求重新查证公开用法"}
{"action":"set_status","entry_id":"稳定ID","expected_revision":3,"status":"understand_only","reason":"只需要理解，不主动说"}
{"action":"disable","entry_id":"稳定ID","expected_revision":4,"reason":"含义有争议"}
```

已有条目写入须匹配 `expected_revision`；真人解释需 displayed `message_ids` 和逐字 `explanation_quote`，操作者纠错允许无新真人消息但必须填写 reason。`list` 有分页及 16000 字符预算，`get` 可回查最近 10 条证据。

`social_memory(kind='slang')` 直接代理同一张 jargon 表、同一稳定 ID 和同一来源校验，保留 list/record/confirm/correct/delete/clear；可额外指定 `term`、`jargon_status`。旧 record 的自由文本只作候选假设；direct/corroborated 确认的释义必须能在真人原文找到，不允许仅给 inference 贴 direct 标签就冒充事实。默认确认态为 understand_only。删除、过期和来源失效统一为 disabled，仍保留旧来源/词形抑制与 clear 水位。

沿用已有 live memory 的每轮刷新，仅将当前文字实际提到的少量词放入独立 `jargon_understanding` 数据区，最多 5 条且与记忆合计受 5000 字符预算约束，带 status/revision、群内义/公开义及“只理解、不主动复用”标记。纠错/删除在下一次模型迭代和后续回合可见。这是旧 slang 理解通路的四态适配；D 的表达/贴纸选择器和生成前精排尚未接入。

## 按需研究和预算

先用本群语境判断。自动研究只针对**新发现、仍不确定、确需查公开用法**的候选；已研究过的同词、普通词、明确本群解释、私有称呼和敏感标签不随每轮聊天反复搜索。工具 submit 的 `research=true` 或 review 会排入同一批次机制，可在不足 10 条新消息时显式复核已有词；查询本身永不联网。

研究通过网关**同一个普通工具注册表**调用 `web_search` / `web_fetch`，服从其启用开关、配置、URL/SSRF/重定向防护和已有代理机制，没有群聊专用权限表或另建 HTTP 客户端。网络工具不可用时保留不确定性，不影响主聊天。

- A/B 默认素材窗口 **10/80 条**、单批最多 20 个黑话候选；可零条。
- 表达和黑话现在共享全局 **并发 1、请求启动间隔至少 300 秒**，按较早待处理批次调度；主聊天运行、待判断或待唤醒时不启动学习。
- 默认每次模型请求 **2048 Token / 30 秒**。发现一次，确实读到正文后才增加一次统一释义请求；每次尝试最多 2 次模型调用，显式复核最多 1 次。原始 provider chat，无隐藏主模型 fallback；批次默认最多 2 次尝试，maxRetries=0 则一次，重启不重置。
- 每批至多 **3 次搜索工具调用、3 次抓取工具调用、12000 字符正文**。计数在调用前持久化，失败/重试不能重置；已读正文可在同批重试复用。这里统计工具调用，普通网页工具内部的安全预取/重定向等既有 HTTP 行为不冒充独立学习工具调用。
- 搜索仅用于发现 URL。抓取需为成功文本正文、至少 100 字符；标题、摘要、图片和错误结果不能作为查证完成。一次统一释义要求来源 URL 与正文连续引句匹配，并且正文涉及目标词；缺来源、编造引句使事务失败，未确认义保持为空。
- 只搜到无关页、无正文、无可靠解释时，保留 candidate/不确定；不会用模型常识填已知含义。群内义与公开义分开写，本群明确含义优先。公开材料存在争议且没有已确认群内义时 disabled；已确认群内特殊义与公开义不同可保持 understand_only 并记 divergent。

批次统计显示模型调用数、Token、搜索/抓取次数、正文字符、耗时及固定错误码；正文与来源保留在已有有界终态批次中（每 scope/类型 25 批），词条保留来源链接及支持引句。不会把任意模型列出的链接当作实际读取来源。

## 纠错与旧义保护

真人新解释或操作者纠错直接更新同一 ID、增加 revision，记录 authority、来源 seq 和 `learning_changes`；覆盖旧本群推断，保留独立公开义及其来源。本批不要求逐条人工批准。

旧证据 ID 被抑制，clear 水位继续有效；旧消息编辑后再次入窗也不能覆盖纠错条目。普通推断不能覆写 human/operator 权威版本；更晚的真人明确解释可更新较早 human 解释，操作者版本通过显式工具纠正。已停用条目不被后台复活。网络进行中发生纠错/删除，提交时修订水位已变则整批拒绝旧结果。条目、证据和黑话游标成功时在同一事务提交，失败不消费消息；复核批次不推进发现游标。

schema 15→16 在原连接事务内为 jargon 增加权威/复核元数据、为 learning_batches 增加 purpose/targets 与研究计数/正文、模型调用数。旧 confirmed 保守改为 understand_only，旧 expired/deleted 改为 disabled，不从旧自由文本猜新含义；实际实例升级前 jargon 为 0。没有新增独立任务表、租约、ID 映射或哈希层。

## 四场景实际验证

执行 `scripts/evaluate_social_jargon.py --config <实际配置> --output /tmp/v5c-verification/actual-scenarios.json`，使用当前 **deepseek-flash**、DuckDuckGo 搜索和现有网页读取器，临时库与合成对话，不挂 sender/receiver、不向真实群发探针。仅离线演示将窗口阈值设为 1，直接运行各批，线上保持 10 条/300 秒。

| 场景 | 实际结果 |
| --- | --- |
| 公开网络梗查证 | 主模型入口提交“栓Q”复核，1 次搜索、2 次抓取，实际读到 [百度百科正文](https://baike.baidu.com/item/%E6%A0%93Q/60856117)。保存公开义及匹配引句/链接，归 understand_only；没有把一次查询当成鼓励主动使用 |
| 群内特殊义 | 真人合成原话“我们群把临时取消的聚会叫蓝票，不是车票。”实际模型识别“蓝票”，群内义为“临时取消的聚会”，understand_only；**0 搜索、0 抓取** |
| 找不到可信义 | 构造“咕噜帧泡泡矩阵”，实际只搜/读到无关网络用语列表；群内义、公开义、来源链接均为空，保持 candidate，没有把无关正文拼成新词义 |
| 纠错覆盖旧版 | 新原话明确“蓝票在我们群专指临时加场，不是取消。”同 ID 更新到 r3；重放旧原话新修订、再次实际模型提取后仍为“临时加场”/r3，没有恢复取消的旧义 |

该次实际验证合计 **4 次模型调用，17525 输入 / 1858 输出 Token；2 次搜索工具调用、3 次抓取工具调用**。公开和无结果两批各最多读取 12000 字符。发现普通词、usable 自动流转、争议 disabled、双链并发/限流、编造正文引句拒收等另由确定性替身回归覆盖。

完整模型/网络报告保留在本机 `/tmp/v5c-verification/actual-scenarios.json`。脱敏固定结果 `tests/fixtures/social_v5c_actual_scenarios.json` 只留结果、检查、正文来源和字符数，不复制整篇网页或来源长引文。这里验证的是合成语境的实际模型/网络行为，不冒充真实群友已经使用这些词；线上不写入合成输入、测试 scope 或虚构释义。
