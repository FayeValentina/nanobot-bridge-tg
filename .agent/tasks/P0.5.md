# 任务 P0.5：主动开话题（idle）和空闲活动（activity）改为两个独立计时器【行为变更：修 bug】

你是本工程的实施者，处于 Claude 编排模式（见 AGENTS.md “Orchestrated implementation mode” 和 `.agent/orchestration.md`）。

## 背景

`docs/SOCIAL_ARCHITECTURE_REVIEW.md` §5.2：`nanobot/channels/telegram/social/proactive.py::SocialProactive.tick` 中，
`elif policy.activity_enabled:` 排在概率 idle 分支之前，所以开启 activity 后，idle 主动开话题永远不会执行。用户确认这是 bug。

**不能只调换判断顺序**：开启 activity 后，唯一的计时器 `next_check` 按 `activity_interval_seconds`（默认 600 秒）推进；
而 idle 的设计是按 `min_interval_seconds..max_interval_seconds`（用户配置为 30–90 分钟）随机间隔检查。
只调换顺序，idle 就会每 10 分钟掷一次骰子，频率远超设计。所以改为两个独立计时器。

## 设计（已定，不得改变）

- `proactive_state.next_check` 继续表示 **idle** 的下次检查时间。新增列 `next_activity_check REAL` 表示 **activity** 的下次检查时间。
- `_next_check(binding)` 拆成两个方法：
  - `_next_idle_check(binding) -> float`：`now + min_interval + random * (max_interval - min_interval)`（即现在非 activity 分支的公式）。
  - `_next_activity_check(binding) -> float`：`now + activity_interval_seconds`。
- `sync(scope, binding)`：
  - `idle_due`：沿用现有逻辑（policy 未变且原值不为空就保留原值，否则在启用时取 `_next_idle_check`，未启用为 None）。
  - `activity_due`：仅当 `enabled and binding.proactive.activity_enabled` 时有值；policy 未变且原值不为空就保留，否则取 `_next_activity_check`。
  - 提前 return 的条件增加一项：`(row["next_activity_check"] is not None) == (enabled and activity_enabled)`。
  - INSERT ... ON CONFLICT 同时写入 `next_activity_check`。
- `tick(scope, binding, config)` 改为以下结构（伪代码，变量名可以不同，但判断顺序和含义必须一致）：
  ```
  row = 读取 proactive_state；row 为空则 return
  idle_ready = row.next_check 不为空 且 <= now
  activity_ready = policy.activity_enabled 且 row.next_activity_check 不为空 且 <= now
  若 idle_ready 和 activity_ready 都为 False：return

  common = 现有公共前置判断链，按现有顺序：stopped / disabled / quiet_hours / deferred / busy（三种）/ member_active，
           命中返回对应字符串，否则为 None。（"missed" 不在这里，见下面每一步。）

  idle_decision = None
  if idle_ready:
      if now >= row.next_check + policy.ttl_seconds: idle_decision = "missed"
      elif common: idle_decision = common
      elif <现有 send_budget 条件>: idle_decision = "send_budget"
      elif <现有 request_budget 条件>: idle_decision = "request_budget"
      else: <现有概率计算与抽样，完全不变> → "scheduled"（candidate = idle）或 "probability_miss"

  activity_decision = None
  if activity_ready:
      if candidate is not None: activity_decision = "idle_selected"
      elif now >= row.next_activity_check + policy.activity_ttl_seconds: activity_decision = "missed"
      elif common: activity_decision = common
      elif <现有 other_topic_active 条件>: activity_decision = "other_topic_active"
      elif <现有 request_budget 条件>: activity_decision = "request_budget"
      else: activity_decision = "scheduled"（candidate = activity，字段与现有代码相同）

  decision = idle_decision，如果 activity 没有被评估（activity_decision is None）且 idle 被评估；
             否则 f"idle:{idle_decision or 'not_due'};activity:{activity_decision}"

  UPDATE proactive_state：
      next_check = _next_idle_check(binding) if idle_ready else 原值
      next_activity_check = _next_activity_check(binding) if activity_ready else 原值
      last_check、decision、opportunity_seq+1、probability、sample、metrics 与现在相同
      selected = int(candidate is not None) if (sample is not None or activity_decision is not None) else None
  candidate 不为空时插入 wake 的 SQL 与现在完全相同
  ```
- `status()` 的 SELECT 加上 `next_activity_check`。不做其他改动。
- `store.py::SocialStore.next_due` 的 UNION 加一行 `UNION ALL SELECT MIN(next_activity_check) FROM proactive_state`。
- schema：`schema.py` 中 `SCHEMA_VERSION` 18 → 19。迁移步骤写在 `schema.py` 现有的 `if version < 18` 之后，与它的写法一致：
  列不存在时 `ALTER TABLE proactive_state ADD COLUMN next_activity_check REAL`；然后
  `UPDATE proactive_state SET next_activity_check=next_check WHERE next_check IS NOT NULL`
  （已有的 activity 计时继续生效；下一次 `sync` 会按 policy 修正）；最后 `PRAGMA user_version=19`。
