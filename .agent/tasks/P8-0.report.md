### 1.4 protocol 变化的实际版本路径与 D4

**当前没有 `SOCIAL_PROTOCOL_VERSION`。** 全仓搜索只在审查文档中找到这个旧名字；生产实现已经直接比较内容。

路径：

1. `ScopeBindings.resolve()` 读取角色正文：`S/bindings.py:228–253`。缓存键是 resolved path，失效依据是 `mtime_ns + size`，不是哈希。
2. `:254` 组装 protocol＋角色＋background。
3. `:257–263` 分别比较：
   - `persona:<session_key>`＝完整 assembled；
   - `scope:<session_key>`＝`{"role_id": ..., "paused": ...}` 的 JSON。
4. `S/db/scopes.py:13–22` 与 `runtime_settings.value` **直接比较**；不同则该 setting revision 加一。
5. `S/bindings.py:264–267` 返回 `persona_revision` 与 scope version。当前所谓 binding revision 在实现中叫 `version`，不是单独的 `binding_revision` 属性。
6. `S/runtime.py:198–206`：persona_revision 不同，**只清空 `session.provider_state`**，更新 `_persona_revision`。
7. 同一 social 模式下，不修改 `last_archived`，不删 summary、checkpoint、pending_user_turn、goal。
8. `S/runtime.py:165–184` → `S/store.py:63–71`：只有 scope version 变了才触发绑定重置。**只改 protocol 不改变该 version，因此不会取消 wake、wait、排队发送或 judge 状态。**
9. 进程重启另由 `S/runtime.py:218–222` 清 provider_state、runtime_checkpoint、pending_user_turn；不清历史或 summary。这是重启路径，不是 protocol 内容比较路径。
10. 只有 social↔ordinary 模式切换执行 `S/runtime.py:207–217` 的历史隐藏：`last_archived=len(messages)`、清部分 metadata。

因此，**沿用当前“assembled 内容→persona_revision”路径的 P8-a 不违反 D4**。不要把模板版本重新接到 scope version，也不要把 `context_version` 改成模板版本；当前 context_version 固定为 `social:<session_key>`，见 `runtime.py:202`。

已有对应断言：`TT/test_social_bindings.py:165–193` 保留历史/metadata，`:196–213` 单独断言模式切换隐藏历史；本任务没有运行它们。

### 5.4 删除 social_mark_read

当前 `mark_read` 与 `acknowledge_seen` **最终可达到的连续水位上限相同，但时机不完全等价**：

- mark_read 可在 turn 中途推进任意已连续展示前缀，`S/store.py:211–222`。
- acknowledge_seen 自动取本 turn 最大连续前缀，再调用同一 mark_read，`:224–231`。
- 自动确认只在没有 turn error/exception、且不是 unsent final 时执行，`S/hook.py:134–139`。

不能通过 mark_read 达到的状态：

- 未展示消息不能标记；
- 其他 turn 展示不算本 turn 展示；
- 不能跨空洞；
- 不能水位倒退或超过 observed history。

以上由 `S/db/views.py:24–29`、`S/store.py:213–220` 强制。

**只靠手动 mark_read 能留下的差异**：先中途标记，随后本 turn 失败或 unsent，已写入的水位仍保留；自动确认不会在该失败回合执行。另外中途推进水位可改变同 turn 后续 read 的页起点。删除后这两种时序变化需接受为行为变更。

线上确实用过 **98 次，96 次未识别为错误，2 次倒退拒绝**，不能描述为“从未使用的死工具”。

## 7. 疑点 / 需要编排者决定的事项

1. **“12→8”与实际保留清单不一致。** §5.3 的保留名字逐个计数为 **9**：send、wait、state、media、sticker、memory、jargon、expression、activity。依据 `D/SOCIAL_ARCHITECTURE_REVIEW.md:469–478`。本任务不自行再合并 expression/jargon 或删除 activity。

2. **P0-6 的版本问题已被 P2-a 提前解决。** 当前直接比较 assembled，无 SOCIAL_PROTOCOL_VERSION；若 P8 新增模板版本，不能重新制造 scope rebind。依据 `S/bindings.py:254–267`、`S/runtime.py:202–222`。

3. **主 protocol 的 intermediary 机制描述已落后于 P7。** 当前 directed、无 selective wait 的真人新对话直接进入主模型，judge 只承担剩余语义判定，且失败回退 wake。依据 `S/judge.py:294–300、355–358`。P8 应按现状重写，不能恢复窄准入或全量 judge。

4. **mark_read 冗余的是成功回合末最终水位，不是全部时序。** 中途分页和后续失败时保留水位是现有差异；线上也有 98 次使用。依据 `S/store.py:211–231`、`S/hook.py:134–139`。

5. **贴纸＋文字无法仅改 schema 实现。** 入队 child 当前没有 kind/media_ref，字符串 marker 放进现有 parts 会作为文字发出。依据 `S/db/deliveries.py:86–87`、`S/delivery.py:193–205`。需要指定内部参数/持久化修改范围。

6. **混合贴纸/文字的 reply target、followup_id、幂等比较需明确。** 当前单条幂等忽略 reply_to/followup_id，parts 比较 reply_to；新 mixed parts 应比较哪些值不可由“吸收 send”四字推定。依据 `S/delivery.py:130–132、180–183`。

7. **角色过滤不仅在生成提示中。** expression 自动学习和 operator modify 都被四词硬过滤；中文学习模板也写死肥鱼。只移 `context.py:68` 不够。依据 `S/expressions.py:103、163、252`、`TP/telegram/social_expression_learning.md:13`、`S/jargon.py:321`。
