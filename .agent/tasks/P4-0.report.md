## 4. 子串匹配可能失效的情形

| 情形 | 漏判／误判边界 | 代码证据及确认程度 |
|---|---|---|
| 相同 JSON 值、不同序列化 | 空格、字段顺序、Unicode 转义等变化后，即使语义相同，完整 body 子串也不相同，不能登记。 | 判定为字符串包含：`social/store.py:194`。**正常两条生产路径没有发现此差异**，保存与编码参数相同：`social/store.py:182`；`social/runtime.py:73–74`。 |
| 外层转义 | 用 `str(messages)`／外层 JSON 文本搜索可能改变引号、反斜线及换行表示；当前 `_note` 特意取 content/text 原值，所以不能把这种外层转义当成已发生的运行时故障。 | `social/runtime.py:849–861`、`:911–921`。 |
| 生成时裁剪 | 快照内的原消息可能被裁短，但裁剪先于 body 保存和 encode，因此本身不破坏 body 匹配；证据只覆盖裁剪后的 excerpt。 | `social/store.py:130–185`；`social/db/views.py:57–62`。 |
| 生成后截断／工具外置 | 新 view JSON 或附加 memory 后的工具 content 超预算，会变成前缀／文件引用，完整 body 不在请求文本中，整份 view 不获资格；已经显示的部分消息也不会单独获得资格。 | `agent/runner.py:539–546`；`agent/context_governance.py:69`、`:709–733`、`:930–949`；`nanobot/utils/helpers.py:402–406`、`:580–612`。social_read_messages 不在 offload 豁免集合中。 |
| 分多次读取外置文件 | 如果模型分段读取 body，且整个 body 从未作为连续子串出现在一次 `_note` 拼接文本中，不能登记；若后来 read_file 返回完整原 body，则可能通过，无需来源仍是 social_read_messages。 | read_file 豁免：`agent/context_governance.py:69`、`:715–717`；匹配不检查 role/tool 名：`social/runtime.py:911–921`；完整 body 条件：`social/store.py:194`。实际分段实例未确认。 |
| 只展示部分 body／跨块边界 | 所有片段间统一加 `\n`；如果 body 被拆开且插入的换行不属于原 body，则完整匹配失败。反之，不同消息／块拼接恰好形成 body 也可通过；不验证同一个消息边界。 | `social/runtime.py:911–921`；`social/store.py:194`。存在可导致该结果的判定语义；实际拼接实例未确认。 |
| 历史裁掉／archiver 摘要 | 历史快照被移除或替换成摘要后，不能证明原 body 仍在当前输入；摘要即使保留某些事实也不给原 view 整体资格。 | session 从 last_archived 之后重放：`nanobot/session/manager.py:353–391`；核心摘要替换 accepted history、保留 delta：`agent/context_governance.py:521–575`；无 compaction 时可 snip：`:638–642`、`:951–990`。 |
| 多模态 | JSON 中的 media/media_details 是文本描述，不是实际像素曝光；图片内容不参与 `_note`。只看到图片而没看到完整 body，不能使该 view seen；看到完整 JSON 则即使没看图片也会 seen。 | `social/store.py:141–142`；`social/runtime.py:911–920`；原生图片内容构造 `agent/context.py:344–373`。 |
| provider 转换 | `_note` 看的是 provider 适配前的整理结果，不是最终 HTTP／服务端实际接收记录。Responses 的 user text、tool string 转换保持字符串，因此这两种普通转换本身未确认会破坏匹配。其他 provider／服务端改写导致的实际误判未确认。 | `agent/runner.py:892–903`、`:999–1016`、`:459`；`providers/openai_responses/converters.py:77–100`、`:103–127`。 |
| provider 续传状态 | adapter 可通过 conversation_state.pending_messages 发送 delta；`context.model_messages` 仍可含本地完整整理历史。因而“该字符串在本地列表中”不等于“本次线上请求重新发送该字符串”。服务端保留内容是否与本地一致未确认。 | `providers/conversation_state.py:110–168`；`agent/context_governance.py:671–690`；`agent/runner.py:459`。 |
| 历史重放、来源不受限 | 一个 seen view 以后不会重新归属另一 turn；未 seen 且 turn=NULL 的旧 view 若在新 turn 历史／其他文本中完整出现，可以被归到新 turn。随机 view_id 降低无意相同字符串的可能，但不阻止原 body 重放。 | `social/db/views.py:26–27`；`social/store.py:194–201`；历史进入 transcript：`agent/context.py:295–307`。真实误归属实例未确认。 |
| view 记录先被清理 | body 仍可能在 transcript 中，但数据库行已因一小时／128 条清理被删除；之后无法登记，shown／evidence 查询也会丢失对应行。 | `social/db/views.py:40–48`、`:16–31`；历史重放 `agent/context.py:306`。长 turn／高频 read 下存在代码条件，实际发生未确认。 |
