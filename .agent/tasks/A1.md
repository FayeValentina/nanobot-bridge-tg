# 任务 A1：主模型连续失败时告警（日志 + Telegram 私信）

你是本工程的实施者，处于 Claude 编排模式（见 AGENTS.md “Orchestrated implementation mode” 和 `.agent/orchestration.md`）。

## 背景

`docs/SOCIAL_ARCHITECTURE_REVIEW.md` §8 A1：主模型 provider 曾连续 28 小时全部返回 HTTP 402（余额不足），owner 毫不知情。
gateway 已经给每个 provider 挂了调用观察者 `nanobot.llm_usage.record_llm_call`（`nanobot/cli/gateway_runtime.py` 中的 `_observe_provider`），
每次物理调用都会收到一个 `LLMCallRecord`（`nanobot/llm_usage/models.py`），里面有 `provider`、`model`、`finish_reason`、`error_status_code`、`error_kind`。
告警挂在同一个观察点上，不改 agent loop / runner / provider。

## 设计（已定，不得改变）

1. 新文件 `nanobot/llm_usage/alerts.py`，只包含一个类：
   ```python
   class ModelFailureAlert:
       def __init__(self, bus: MessageBus, config: ModelFailureAlertConfig) -> None: ...
       def observe(self, call: LLMCallRecord) -> None: ...
   ```
   - 状态只放内存：`dict[tuple[str, str], _State]`，键是 `(call.provider, call.model)`；`_State` 是一个小 dataclass，字段为
     `failures: int`、`alerted: bool`、`last_status: int | None`、`last_kind: str | None`。重启后状态清零，这是预期行为。
   - 判定：`call.finish_reason == "cancelled"` → 忽略，直接 return。
     `call.error_status_code is not None or call.finish_reason == "error"` → 失败。其余 → 成功。
   - 失败：`failures += 1`，记录 `last_status/last_kind`。当 `failures == config.consecutive_failures` 且 `not alerted` 时：
     `logger.error("Model {provider}/{model} failed {n} consecutive calls (status={status}, kind={kind})", ...)`，
     如果 `config.chat_id` 非空，就发送告警私信，然后 `alerted = True`。之后继续失败不再发送。
   - 成功：如果 `alerted` 为真：`logger.info("Model {provider}/{model} recovered")`，`chat_id` 非空时发送恢复私信。
     然后把该键的状态重置为初始值（或直接删除该键）。
   - 发送方式：`asyncio.get_running_loop().create_task(self._bus.publish_outbound(OutboundMessage(channel=config.channel, chat_id=config.chat_id, content=text)))`；
     把 task 存进 `self._tasks: set` 并在完成时移除，避免被回收。观察者总是在事件循环中被调用，不需要处理没有运行中循环的情况。
   - 文案（固定，中文）：
     - 告警：`⚠️ 主模型连续 {n} 次调用失败：{provider}/{model}，HTTP {status 或 "无"}（{kind 或 "未知"}）。机器人暂时无法正常回复，请检查账户余额或模型配置。`
     - 恢复：`✅ 主模型已恢复：{provider}/{model}。`
2. 配置：在 `nanobot/config/schema.py` 新增
   ```python
   class ModelFailureAlertConfig(Base):
       channel: str = "telegram"
       chat_id: str = ""            # 为空时只写日志，不发私信
       consecutive_failures: int = Field(default=3, ge=1, le=100)
   ```
   并在 `GatewayConfig` 中加字段 `model_failure_alert: ModelFailureAlertConfig = Field(default_factory=ModelFailureAlertConfig)`。
   JSON 键按项目惯例是 camelCase（`modelFailureAlert`、`chatId`、`consecutiveFailures`），使用现有 `Base` 的别名机制即可，不要另写别名。
3. 装配：`nanobot/cli/gateway_runtime.py` 中，`bus = MessageBus()` 之后创建
   `model_failure_alert = ModelFailureAlert(bus, config.gateway.model_failure_alert)`；
   `_observe_provider` 中把 `snapshot.provider.set_llm_call_observer(record_llm_call)` 改为传入一个函数：先调用 `record_llm_call(call)`，再调用
   `model_failure_alert.observe(call)`。这个函数定义在 `_observe_provider` 外、`gateway_runtime.py` 内的同一作用域，命名为 `_observe_llm_call`。
   不改动其他装配逻辑。
4. 在 `nanobot/llm_usage/__init__.py` 的 `__all__` 中**不要**导出新类，调用方直接从 `nanobot.llm_usage.alerts` 导入。
