### 现有 Pydantic schema 对比事实

只读调用 schema 生成并比较得到：

```text
social_activity equals_model=True
social_jargon equals_model=True
social_expression equals_model=True
social_memory equals_model=True
```

这四个工具当前**没有并存的手写 schema**，就是直接返回模型结果，见 `U:50–57`；因此不能把它们描述为“待从手写迁移到模型”。

| 模型 | 当前字段顺序、required 和关键事实 |
|---|---|
| `ActivityRequest`，`S/activity.py:17–27` | action, activity_id, expected_revision, title, goal, motivation, checkpoint, next_step, artifacts；仅 action required；revision 使用 `minimum=1`；可空字段生成 anyOf/null |
| `JargonRequest`，`S/jargon.py:92–109` | action, entry_id, term, aliases, local_meaning, explanation_quote, message_ids, origin, expected_revision, status, research, query, include_inactive, reason, limit, offset；仅 action required；revision 是 `exclusiveMinimum=0`；limit 1–50、offset 0–1000000 |
| `ExpressionEdit`，`S/expressions.py:79–91` | action, entry_id, expected_revision, situation, expression, tone, intent_category, scene_tags, suitable, unsuitable, reason；仅 action required；revision 是 `exclusiveMinimum=0` |
| `MemoryRequest`，`S/memory.py:28–42` | **继承字段在前**：pending_question, pending_thought, motivation, followup_at, followup_state, state_reason；随后 action, origin, memory_id, kind, content, message_ids, member_ids, basis, ttl_seconds, query, include_inactive, limit, offset；仅 action required。继承定义见 `S/followups.py:16–22` |

共同输出事实：

- 四个模型顶层键顺序是 `additionalProperties, properties, required, title, type`；字段有生成的 `title`，普通默认值会进入 `default`。
- 当前手写外层键顺序是 `type, properties, required, additionalProperties`，send 后附 `oneOf`，见 `U:119–121`。
- 两个空参数工具当前显式有 `required=[]`，`U:58–59,119`；现有四个模型均因 action 必填而有 required，不能据此推断尚未定义的空请求模型是否保留空 required。
- `MemoryRequest.check_action` 的跨字段规则不等于 JSON schema required，例如 record 所需 kind/content/evidence，见 `S/memory.py:44–69`。
- sleep_interrupts 已经使用模型生成，`U:114`；模型仍包括 `probability` 字段，见 `nanobot/config/schema.py:95–103`。

**其余 8 个工具尚无对应请求模型**；全仓库现有请求／编辑模型只有上述四个。因此未来字段顺序、description、minimum/maximum、required 是否改变，取决于新模型定义，当前无法给出其“实际生成差异”。

可以确定需要逐项保留的现有特殊形状是：send 的 oneOf 和两段 description，sticker 的 action 条件语义／notes item schema／set_name description，set_wake 的嵌套 sleep schema，以及上表全部范围约束。普通 Optional 字段、默认值、模型 title 的生成形式与当前手写输出并非逐字一致。
